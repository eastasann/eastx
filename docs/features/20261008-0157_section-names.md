# Feature Design Doc — セクション名を英語に揃え、作品を Lab にする

> 原則: 1ユーザーストーリー = 1 Feature Design Doc
> 変更規模: 小（既存の画面の文言だけ。新しい画面・スキーマ・API の変更なし。URL も変えない）

## 背景と目的

公開サイトの /ja のセクション見出しのうち「作品」「コーディング記録」は、英語の Works・Coding Log を訳した語で、日本語として違和感がある。刷新した公開サイトでは、セクション見出しは小さなグレーのラベルで、英語のラベルの方が見せ方に合う。

また「作品」と「プロジェクト」の違い（個人で作ったものか、仕事で作ったものか）が、日本語の「作品／プロジェクト」でも英語の「Works／Projects」でも伝わらない。個人で作ったものを「Lab」（試して作る場所）と呼び、仕事の「Projects」と並べて違いを見せる。

持ち主が決めたこと（2026-10-08）:

- 公開サイトのセクション見出しは、/ja も /en も同じ英語の名前にする。
- 個人で作ったもの（今の「作品」）は「Lab」、仕事で作ったもの（今の「プロジェクト」）は「Projects」にする。
- 詳細ページの戻るリンクはセクションの英語の名前にする。前後のリンクと注記は文なので日本語のまま、「作品」という語を使わない言い方にする。
- 管理画面のメニュー・一覧・編集ビューの名前も、公開サイトと同じ名前にする。

## Goal / Non-Goal

### Goal

1. セクション名を日英共通の英語にする（「名前の対応」の表）。公開側の P1 のセクション見出しと、セクション内ページングの読み上げ名（「{セクション名}のページ」）に使う。
2. /ja のページで英語のセクション名を出す要素には `lang="en"` を付ける（読み上げを英語の発音にする。design-spec 1.4 の「ページの言語の宣言」）。
3. 詳細ページ（P2〜P5）の戻るリンクの見える文字を「← {セクション名}」（日英共通）にする。読み上げの名前は「{セクション名} へ戻る」（/ja）・「Back to {セクション名}」（/en）にし、見える文字を名前に含める（ラベルと名前の一致）。
4. 詳細ページの前後のリンクと注記を、「作品」「Works」という語を使わない言い方にする（「詳細ページの文言」の表）。
5. 管理画面の、6つのセクションの名前（メニュー・一覧ビューの題・編集ビューの題と戻るリンク・ダッシュボードの件数カードと下書きの一覧の種類）を、公開サイトと同じ英語の名前にする（「管理画面の文言」の表）。ダッシュボード・プロフィールはそのまま。

### Non-Goal

- URL（`/works`・`/projects`・`/coding` など）、API のパス（`/api/admin/works` など）、DB のテーブル名・カラム名、コードの識別子（`work`・`WorkRow` など）の変更。外から見える URL は変えず、内部の名前は「作品＝work」のまま。
- ドキュメントの中の概念の名前（A5「作品管理」、SDD の「作品」など）の変更。ドキュメントは今どおり概念を「作品」「プロジェクト」と呼び、画面に出す名前だけを「名前の対応」の表で決める。
- コーディング記録の種類（学習ログ・コード断片・問題を解いた記録・技術メモ）、経歴の種類（職歴・学歴）など、セクション名以外の文言の変更。
- 中身（タイトル・本文）や、デモデータ・移行データの変更。
- OGP 画像の変更（セクション名を含まない）。

## 実装アプローチ

- 公開側の文言はすべて辞書（ADR-013）にあるので、辞書の値を変える。辞書のキー（`works`・`prevWork` など）はコードの識別子なので変えない（Non-Goal）。
- 管理画面の文言は辞書を使わず各画面に日本語で直接書いている（SDD 9章）ので、各画面の名前の定数（`KINDS` の `name` など）を変える。
- /ja の英語のセクション名の `lang="en"` は、セクション見出しの部品（`SectionHeading`）と戻るリンクで、表示中の言語が `ja` のときにだけ付ける。

## テスト方針

| テスト種別 | 対象 |
|-----------|------|
| Unit | 辞書の日英の対応（`en.ts` が `ja.ts` の型を満たす。今のテストのまま）。セクション名が日英で同じ値であること |
| Integration | なし（API の変更がない） |
| E2E | /ja の P1 のセクション見出しが英語の名前で、`lang="en"` が付いていること。/ja の作品の詳細ページの戻るリンクが「← Lab」で、読み上げの名前が「Lab へ戻る」であること。前後のリンクが「前へ」「次へ」であること。管理画面のサイドメニューに「Lab」があり、押すと作品の一覧が開くこと。今の E2E が使う文言（「作品」「作品の一覧」など）を新しい名前に直したうえで、すべて通ること |
| アクセシビリティ | 今の axe の検査（P1〜P5・A1・A2・編集ビュー）で重大な違反が0件のまま |

## ロールアウト計画

1. 実装を PR で `main` に入れる。`make lint`・`make typecheck`・`make test`・`make e2e` が通ること。
2. `make promote ENV=staging` で staging に出し、/ja と /en のトップ・作品の詳細ページ・管理画面のサイドメニューで名前を確かめる。
3. 同じ SHA を `make promote ENV=production` で本番に出す。
4. 戻すときは昇格 PR を revert する（データを変えないので、そのまま戻せる）。

## 実装時に決めた細部

- セクションの名前は `src/i18n/section-names.ts` の1か所に持ち、公開側の日英の辞書と管理画面が同じ値を使う。
- 英語の名前に日本語の語を続ける文言は、間に空白を入れる（「Lab のページ」「Lab へ戻る」「Lab の新規作成」「Lab の一覧」）。
- 使用技術の一覧の列「使っている作品・プロジェクト」と削除の確認の文も、セクションの名前を使って「使っている Projects・Lab」にした（Goal 5 の「管理画面の種類の名前」に含まれる）。
- `lang="en"` は、セクションの名前が日英とも英語なので、表示中の言語に関わらず見出しと戻るリンクの名前に付ける（/en では冗長だが害はなく、表示中の言語を部品に渡さずに済む）。
- 戻るリンク・ページングのまとまり・使用技術の並びの読み上げの名前は、aria-label ではなく中身の要素（または aria-labelledby で指す要素）で作る。aria-label にすると、名前の部分に付けた `lang="en"` が読み上げに効かないため。そのため辞書の `back.*` は、名前の前後に足す語を返す `backLink`、`paging.controls(section)` は続く語だけの `paging.controlsSuffix` に置き換えた。
- 作品とプロジェクトで同じ文言になった辞書のキーはまとめた（前後のリンクは `neighbor.previous`・`neighbor.next`、注記は `notice.bodyOnlyIn`）。
