# Feature Design Doc — favicon を持ち主のキャラクターの絵にする

> 原則: 1ユーザーストーリー = 1 Feature Design Doc
> 変更規模: 小（静的アセットと `<head>` のリンクだけ。画面・API・スキーマの変更なし）

## 背景と目的

今の favicon は、アクセントの色の角丸の四角に「e」の線を描いた SVG（`scripts/og/generate.ts` がトークンの色から作る）。持ち主が用意したキャラクターの絵（黒の地に生成りの円、その中にスプーンを持つ黒い人物。1254×1254 の PNG）に替え、ブラウザのタブやブックマークで持ち主のサイトだと分かるようにする。

持ち主が決めたこと（2026-10-08）: 絵の円の部分だけを切り抜き、円の外は透明にする（16px でも顔とスプーンが分かり、明るいタブでも暗いタブでも黒い四角に見えない）。

## Goal / Non-Goal

### Goal

1. 公開側と管理画面のすべてのページの favicon を、元の絵の円の部分を切り抜いた PNG（円の外は透明）にする。
2. iOS のホーム画面に追加したときのアイコン（`apple-touch-icon`）を用意する。iOS は透明を黒以外で埋めるので、円の外接正方形で切り抜き、角は元の絵の黒のままにする。
3. 元の絵をリポジトリに置き、favicon とホーム画面のアイコンを `scripts/og/generate.ts` から作り直せるようにする（今の OGP 画像と同じ仕組み）。

### Non-Goal

- OGP 画像（`public/og/default-{ja,en}.png`）の見た目の設計の変更。スクリプトを流すと作り直され、辞書の変更（セクションの名前）が反映される分は含む（「実装時に決めた細部」）。
- Web アプリのマニフェスト（`manifest.webmanifest`）や Android 向けのアイコン。
- ヘッダーのサイト名など、ページの中への絵の表示。

## 影響範囲

| 影響箇所 | 変更内容 |
|----------|----------|
| フロントエンド | `src/routes/__root.tsx` の `<link rel="icon">` を PNG にし、`<link rel="apple-touch-icon">` を足す |
| 静的アセット | `public/favicon.svg` を消し、`public/favicon.png`（64×64、円の外は透明）と `public/apple-touch-icon.png`（180×180、角は黒）を足す |
| スクリプト | `scripts/og/generate.ts`: SVG の favicon をやめ、`scripts/og/favicon-source.png`（元の絵）から2つの PNG を作る |
| バックエンドAPI | 変更なし |
| DBスキーマ | 変更なし |
| 認証・認可 | 変更なし |
| インフラ | 変更なし（`public/` の静的アセットとして Worker を通さずに返る。SDD 4章） |

ソースドキュメントの変更（実装の完了後に /draft:feature-implement が所有権マップに従って直す）:

| ドキュメント | 節 | 変え方 |
|---|---|---|

## 実装アプローチ

- 切り抜きは、OGP 画像と同じく Playwright の Chromium で撮る。円の外接正方形（元の絵の x 193・y 185 から一辺 870px）を、CSS で拡大縮小して表示の大きさに合わせ、favicon は `border-radius: 50%` で円にして透明の地で撮る（`omitBackground`）。ホーム画面のアイコンは円にせず、そのまま撮る。画像の加工のための依存（ImageMagick・sharp など）は足さない。
- favicon は 64×64 の1枚にする（ブラウザが 16・32px に縮める）。`favicon.ico` は作らない（`<link rel="icon">` を読むブラウザだけを対象にする）。
- 元の絵は生成の入力で、色をトークンから作らないので、トークンを変えても favicon は変わらない。

## 詳細設計

### API変更

なし。

### UI変更

`<head>`:

```html
<link rel="icon" href="/favicon.png" type="image/png" sizes="64x64">
<link rel="apple-touch-icon" href="/apple-touch-icon.png">
```

### データマイグレーション

なし。

## テスト方針

| テスト種別 | 対象 |
|-----------|------|
| Unit | なし（スクリプトの出力は画像で、目で確かめる） |
| Integration | なし |
| E2E | 公開側と管理画面のページの `<head>` に、`/favicon.png` の icon と `/apple-touch-icon.png` のリンクがあり、どちらも画像として 200 で返ること |
| 目視 | 生成した PNG を 16・32px に縮めて、明るい背景と暗い背景で見る |

## ロールアウト計画

1. 実装を PR で `main` に入れる。`make lint`・`make typecheck`・`make test`・`make e2e` が通ること。
2. staging に昇格して、ブラウザのタブに新しい favicon が出ることを確かめる（ブラウザのキャッシュがあれば再読み込みする）。
3. 本番に昇格する。戻すときは昇格 PR を revert する。

## 実装時に決めた細部

- `scripts/og/generate.ts` を流すと OGP 画像も作り直される。OGP 画像はセクションの名前（辞書の `section`）を描いているので、セクションの名前を英語にした変更（`docs/features/20261008-0157_section-names.md`）の後に作り直していなかった分が、ここで「Career · Lab · Blog」に変わる。あの FDD の Non-Goal の「OGP 画像（セクション名を含まない）」は誤りで、作り直しをこの変更に含める。
- 元の絵の円の外接正方形（x 193・y 185、一辺 870px）は、ImageMagick で円の生成りの部分の範囲を測った値。絵を差し替えたら測り直す（スクリプトのコメントに書いた）。
