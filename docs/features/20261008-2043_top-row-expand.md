# Feature Design Doc — トップの行は押して広げ、行き先は広げた中に置く

> 原則: 1ユーザーストーリー = 1 Feature Design Doc
> 変更規模: 中（既存の画面 P1 の中の変更で、新しい画面・スキーマ・API の変更はない。訪問者のコアフロー（design-spec 2.2）の「作品・プロジェクトの詳細へ進む」操作が変わるので、大きい方に倒した）

## 背景と目的

刷新した P1（`docs/features/20261007-1427_site-redesign.md`）を実際の内容で見て、持ち主が次の4点を問題にした（2026-10-08）。

1. 作品・プロジェクトの行は、▸ のほかの部分を押すと詳細ページや外部のサイトへ移る。▸ は小さく、行のどこを押すかで結果が分かれるので、広げようとして別の画面へ移ってしまう。
2. 1行目の左（`タイトル ~ 概要`、経歴は `所属 ~ タイトル`）は「…」で切るが、切れた文字を読む手段がない。経歴を広げても所属・タイトルの全文は出ず、作品・プロジェクトでも広げた中に概要は出るがタイトルは切れたまま。
3. 広げた中の使用技術は最大6個と「+N」で、作品・プロジェクトで使った技術をすべて確かめられない。
4. モバイル幅の経歴の行で、2行目の期間はタイトルの開始位置まで字下げされ、広げた中（`種類ラベル · 場所`・内容）は ▸ の左端から始まる。左端が2か所あり、期間がずれて見える。

site-redesign の FDD は「行全体を押して広げ、広げた中に『詳細を見る』を置く」案を、詳細ページへ移るのに1回多く押すことになるという理由で退けていた。実際に使うと、押し間違いで画面を移る損の方が、1回多く押す手間より大きかった。そこで、行は押すと広げる・閉じるだけにし、詳細ページ・外部のサイト・GitHub への入口は広げた中に文字のリンクで置く。広げた1行目は折り返して全文を出し、切れた文字は行を広げれば読めるようにする。

持ち主が決めたこと（2026-10-08）:

- 経歴・作品・プロジェクトの行は、行のどこを押しても広げる・閉じる。
- 作品の行の右の外部リンク・GitHub のアイコンと、外部へ移る行の「別タブで開く」アイコンは行から外し、入口は広げた中にそろえる。
- 広げた中の使用技術は、アイコンだけで全部を折り返して並べる（表示名は今どおりポインターを重ねたときと読み上げで出す）。
- ブログ・コーディング記録の行（広げるものが無く、押すと詳細へ移る）は今のまま。切れたタイトルは詳細ページで読める。
- モバイル幅の2行目と広げた中は、すべて ▸ の左端に揃える。
- 作品・プロジェクトの閉じた行から `~ 概要` を外す（PC 幅も）。概要は広げた中に全文で出るので2回見せず、閉じた行で「…」で切れる行を減らす。

## Goal / Non-Goal

### Goal

1. 経歴・作品・プロジェクトの行は、広げるものがあれば行全体を1つのボタンにし、押すと広げる・閉じる（▸ ⇄ ▾）。行の中にリンクを置かない。
2. 作品・プロジェクトの詳細ページ・外部のサイト・GitHub への入口は、広げた中の最後に文字のリンクで並べる。
3. 作品・プロジェクトの閉じた行は、どの画面幅でも `~ 概要` を出さず、左にタイトルと言語ラベルだけを出す。
4. 広げた行の1行目は「…」で切らず、折り返して全文を出す。作品・プロジェクトは広げると右の使用技術のアイコンを隠す（広げた中に全部出るため）。
5. 広げた中の使用技術は、上限を外して全部をアイコンで折り返して並べる。
6. モバイル幅（<768px）の経歴の2行目（期間）と、すべての行の広げた中の左端を、▸ の左端に揃える。
7. 広げるものも行き先も無い作品の行は、▸ を出さず、押せず、ホバーで地を変えない（今どおり）。

### Non-Goal

- ブログ・コーディング記録の行の変更（持ち主の決定。押すと詳細へ移り、タイトルは詳細ページで全文を読める）。
- 広げるものも行き先も無い作品（タイトルだけの作品）の、切れたタイトルを読む手段。公開中の作品で、概要・サムネイル・使用技術・詳細本文・外部リンク・GitHub のどれも持たないものは、タイトルの長さが行に収まる前提で扱う（今のデモデータと移行データには無い）。
- ツールチップ（`title` 属性を含む）で切れた文字を出すこと。タッチ端末で出せないため、広げて読む形にそろえる。
- 詳細ページ（P2〜P5）・戻るリンク・ページング・セクションの並び順の変更。詳細ページから戻ったとき行を閉じた状態で描くこと（design-spec 6.1.3）も今どおり。
- 広げた行をページングや画面の移動をまたいで覚えること。
- API・DB・公開側のサーバー関数（`getTopPage` の形）の変更。行に必要な値（`hasDetail`・`linkUrl`・`githubUrl`・`stacks` の全件）はすでに返している。

## 実装アプローチ

- 行のヘッダー（▸・名前・言語ラベル・右のメタ）を丸ごと1つの `<button>` にする。`aria-expanded`・`aria-controls` を持ち、読み上げ名は今どおり行の名前だけ（`aria-labelledby`。作品・プロジェクトはタイトル、経歴は `所属 ~ タイトル`）。ボタンの中に右の使用技術のアイコン（読み上げ名つきの `img`）が入っても、名前は `aria-labelledby` で決まるので長くならない。行の中にリンクを置かないので、今の「タイトルのリンクの `::after` を広げる」作り（`stretchedLink`・`linkArea`）と、▸ をリンクの上に重ねる作りは要らなくなる。
- ボタンの中の使用技術の並び（`ul`）はボタンの中に置けない（`button` の中身はフレージング内容だけ）。行の右のアイコンの並びは `span` の並びにし、まとめの名前（「使用技術」）は今の `StackListName` と同じく読み上げ用の要素で持つ。広げた中の並びは今どおり `ul`。
- 広げるものがあるか（`isExpandable`）は、経歴はいつも真（種類ラベルを必ず持つ）、プロジェクトはいつも真（期間を持つ）、作品は「サムネイル・概要・使用技術・詳細本文・外部リンク・GitHub のどれかがある」。今の `hasDetailToShow` に行き先の3つを足す。表示の規則で、`src/domain/`（公開側と管理画面で共通の判定）には当たらないので、`src/site/row-rules.ts` に置いてユニットテストで確かめる（SDD 10章のユニットの対象に足す）。
- 広げた中の包み（`aria-controls` が指す要素）は閉じているあいだも DOM に残し、中身だけを広げたときに描く（今どおり）。`aria-controls` が無い id を指さない。
- 左端の揃え方: 行のボタンの左の余白は今の行と同じ `inset-dense` で、▸ のアイコンの左端・モバイル幅の2行目・広げた中（今の `expandedArea` の `px: inset-dense`）の左端が同じ位置になる。1行目の名前だけが ▸ のアイコンと右の余白（今の `inline`）の分だけ右から始まる。使うトークンは今のセマンティック層の `inset-dense`・`inline` だけで、`docs/06_design-tokens.json` は変えない。
- フォーカスの印は、行のボタン全体に今のフォーカスの枠（アクセントの色。design-spec 4.4）を出す。
- 「詳細を見る」の辞書のキーは、今の `action.visitSite`・`action.github` にそろえて `action.viewDetails` にする。
- 採らなかった案:
  - タイトルの文字だけを行き先へのリンクにし、ほかの部分で広げる: 押せる範囲が文字の幅に限られ、スマホで押し分けにくい。
  - 行は ▸ だけで広げ、ほかの部分は押せない: 押せる範囲が ▸ だけで小さい。ホバーで地が変わらない帯が行のほとんどを占める。
  - 外部リンク・GitHub のアイコンを行に残す: 行の中に「押すと広がる所」と「押すと外へ移る所」が混ざり、1 の押し間違いが残る。
  - 広げた中の使用技術をアイコンと表示名のチップにする: 持ち主がアイコンだけを選んだ。表示名はポインターを重ねたとき（今の `title`）と読み上げで出る。

## 詳細設計

### API変更

なし。

### UI変更

#### 行の操作（経歴・作品・プロジェクトで共通。design-spec 6.1.3 の「行を広げる」を置き換える）

| 項目 | 仕様 |
|---|---|
| 押せる範囲 | 広げるものがある行は、行全体（▸・名前・言語ラベル・右のメタ・モバイル幅の2行目・行の余白）が1つのボタン。押すとその場で広げる・閉じる（▸ ⇄ ▾）。ページは移らない |
| 広げた中 | 広げた中の文字のリンク（詳細を見る・サイトを見る・GitHub）だけが押せる。ほかの部分（期間・サムネイル・概要・使用技術・内容）は押しても何も起きない。経歴の内容（Markdown）の中のリンクは今どおり押せる |
| 1行目 | 閉じているときは今どおり「…」で切る。広げると切らずに折り返して全文を出す。作品・プロジェクトは、広げると右の使用技術のアイコンを隠し、タイトルと言語ラベルだけにする。経歴は広げても `所属 ~ タイトル` と右の期間（デスクトップ幅）を出し、1行目が折り返したときは、期間を1行目の先頭の行の高さに揃える |
| ホバー | 広げるものがある行は、ホバーで地の色を変える（経歴も含む）。広げたあとも行のボタンの部分はホバーで地を変える（押すと閉じるため）。広げた中は地を変えない |
| フォーカス | 行のボタン全体にフォーカスの枠を出す |
| 広げるものが無い作品 | ▸ を出さずにその幅を空けて名前の位置を揃え、押せず、ホバーで地を変えない |
| キーボード | 行のボタンにフォーカスし、Enter・Space で広げる・閉じる。広げた中のリンクは、行のボタンの次に Tab で移る |
| そのほか | 複数の行を同時に開ける。ページを切り替えたら閉じる。言語の切り替え・詳細ページから戻ったときは閉じた状態で描く（今どおり） |

#### 各セクションの表示（design-spec 6.1.4 の経歴・プロジェクト・作品の行を置き換える）

| セクション | 閉じた行 | 広げた中（上から） |
|---|---|---|
| 経歴 | 左に ▸、`所属 ~ タイトル`（所属が無ければタイトルだけ）と言語ラベル、右に期間 | `種類ラベル · 場所`（場所が無ければ種類ラベルだけ）、内容（Markdown の全文。無ければ出さない） |
| プロジェクト | 左に ▸、タイトルと言語ラベル（`~ 概要` は出さない）、右に使用技術のアイコン（最大3個と「+N」）。「別タブで開く」アイコンは出さない | 期間、左にサムネイル（設定したものだけ）・右に概要（全文）、使用技術のアイコン（全部。折り返す）、入口のリンク（下の表） |
| 作品 | 左に ▸、タイトルと言語ラベル（`~ 概要` は出さない）、右に使用技術のアイコン（最大3個と「+N」）。外部リンク・GitHub のアイコンは出さない | プロジェクトと同じ形で、期間は無い |

広げた中で、サムネイル・概要・使用技術・入口のリンクの無いものは、その場所を空けずに詰める（今どおり）。

モバイル幅（<768px）の閉じた行（今どおり）: 経歴は1行目に ▸ と `所属 ~ タイトル`・言語ラベル、2行目に期間。作品・プロジェクトは1行で、デスクトップ幅と同じく左に ▸ とタイトル・言語ラベル、右に使用技術のアイコン（最大3個と「+N」）。

入口のリンク（広げた中の最後に、この順で横に並べる。無いものは詰める）:

| リンク | 出す条件 | 行き先 | 文言（/ja ／ /en） |
|---|---|---|---|
| 詳細を見る → | 詳細本文がある（`hasDetail`） | 作品詳細（P2）／プロジェクト詳細（P3）。同じタブ | 詳細を見る ／ View details |
| サイトを見る ↗ | 外部リンクがある | 外部リンクを別タブ | サイトを見る ／ Visit site（今の辞書の `action.visitSite`） |
| GitHub ↗ | 作品で GitHub がある | GitHub を別タブ | GitHub（今の辞書の `action.github`） |

- 見た目は本文中のリンクと同じ（濃い色と下線。アクセントにしない。design-spec 4.4）。別タブで開くものは ↗ を付け、読み上げに「別タブで開く」を足す（今の `label.opensInNewTab`）。
- 今の「詳細本文なし・外部リンクあり → 行を押すと外部リンク」「作品で外部リンクも無ければ GitHub」という行の行き先の決め方はなくなる。入口はあるものを全部出す。

| Unit | `isExpandable`: 経歴とプロジェクトはいつも真。作品は、サムネイル・概要・使用技術・詳細本文・外部リンク・GitHub のどれか1つだけを持つときに真、どれも無いときに偽（Goal 7 はデモデータに該当する作品が無いので、ここで確かめる） |
| Integration | なし（API・サーバー関数の変更がない） |
| E2E | 作品・プロジェクト・経歴の行の名前の部分を押すと、ページを移らずに広がり（`aria-expanded`）、もう一度押すと閉じる。行のボタンにフォーカスして Enter・Space で広げ、Tab で広げた中のリンクへ移れる。デスクトップ幅で、作品・プロジェクトの閉じた行に概要の文字が無い。作品を広げると、右の使用技術のアイコンが隠れ、広げた中に概要の全文が出る。モバイル幅で、長いタイトルの作品（シードで長くするもの）は閉じた行で「…」で切れ、広げると1行目が折り返して全文が出る。経歴を広げると `所属 ~ タイトル` が切れずに出る。広げた中の「詳細を見る」で作品詳細へ移る。詳細本文の無い作品で「サイトを見る」「GitHub」が別タブで開く。閉じた行に外部リンク・GitHub のリンクが無い。使用技術が7個以上の作品を広げると、全部のアイコンが出て「+N」が無い。モバイル幅で、経歴の2行目の期間・経歴の広げた中・作品の広げた中の先頭の左端が、▸ の左端と同じ。今の E2E の「▸ のほかの部分は行き先へ移る」「作品の ▸ をキーボードで広げる」などは、この振る舞いに書き換えたうえで通す |
| アクセシビリティ | 今の axe の検査（P1 のライト・ダーク）で重大な違反が0件のまま。経歴・作品・プロジェクトを各1行広げた状態の P1 も検査する |
| Lighthouse | 長いタイトルにしたシードのままで、今の P1 の目標を満たす |

## ロールアウト計画

1. 実装を PR で `main` に入れる。`make lint`・`make typecheck`・`make test`・`make e2e` が通ること。
2. `make promote ENV=staging` で staging に出し、/ja と /en の P1 で、経歴・作品・プロジェクトを PC 幅とスマホ幅で広げ、入口のリンクと左端の揃い方を確かめる。1行目の折り返しは、staging のデータでスマホ幅の閉じた行が「…」で切れている行（移行したデータの経歴など）で確かめる。そういう行が無ければ、折り返しは E2E の確認だけにする（シードは staging に入らない）。
3. 同じ SHA を `make promote ENV=production` で本番に出す（SHA を省くと staging に出した SHA を使う）。
4. 戻すとき: staging で問題が出たら本番へは昇格しない。本番で問題が出たら本番の昇格 PR を revert し、`deploy/production/version` を前の SHA に戻す。どちらの場合も、次の昇格の前に `main` で実装の PR を revert するか、直す PR を入れる（昇格 PR の revert では `main` は戻らない）。データを変えないので、戻すのはコードだけで済む。
