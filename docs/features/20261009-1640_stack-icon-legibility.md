# Feature Design Doc — 使用技術のアイコンをダークモードでも見えるようにする

> 原則: 1ユーザーストーリー = 1 Feature Design Doc
> 変更規模: 小（既存の画面の見た目の修正。API・スキーマの変更なし）

## 背景と目的

公開側の使用技術の並び（P1 の Tech Stack、作品・プロジェクトの行と広げた中、P2/P3）のアイコンは、縦横比と色のばらつきをそろえるためにグレースケールで出している（design-spec 4.4）。持ち主が P1 の Tech Stack をライト・ダークの両方で見て、見づらいと感じた（2026-10-09）。原因は次の3つ。

- ダークモード: 黒や濃い色の単色のアイコン（Next.js・Express・vercel・railway・Nx・lerna・GitHub・apollo・Prisma など）が、暗い地の上でほとんど見えない。アイコンの画像は白い地を前提に作られていて、グレースケールにしても明るさは変わらないため。
- ライトモード: 色の薄いアイコン（React・Node.js・Firebase など）は、グレースケールにすると薄いグレーになり、白い地に沈む。
- P1 の Tech Stack: リンクを持つチップにだけ ↗ が付くので、半分ほどのチップの後ろに記号が並び、並びが乱れて見える。

持ち主が決めたこと（2026-10-09）:

- ダークモードでは、グレースケールにしたアイコンを白黒反転する。ダークの画面は、ライトの画面を白黒反転した見え方になる。ライトで見える組み合わせはダークでも見える。技術ごとの設定（ダーク用のアイコンや反転のスイッチ）は持たない。
- ライトモードで薄いアイコンを濃くする。
- P1 の Tech Stack のチップでは ↗ を見せない。

## Goal / Non-Goal

### Goal

1. 公開側の使用技術の並びのアイコン（グレースケールで出している場所すべて）を、ダークモードでは白黒反転して出す。
2. 同じ場所のアイコンの中間から明るい側の濃さを、トーンカーブで濃くする。黒（0）と白（1）は動かさない。白黒反転の前にかけるので、ライト・ダークの両方に効く。
3. P1 の Tech Stack のチップでは ↗ を見せない。読み上げの「別タブで開く」は残す。P2/P3 のチップの ↗ はそのまま残す。

### Non-Goal

- 元の色で出すアイコン（プロフィールの自己紹介の太字の前のアイコン、管理画面のアイコン）の見え方。どちらも元の色を出す決まり（design-spec 4.4）で、白黒反転すると色相が変わる。管理画面は登録した画像そのものを確かめる場所なので、加工しない。自己紹介の太字の前のアイコンも、ダークモードでは黒い単色のアイコンが見えにくいが、持ち主の判断（2026-10-09）で変えない。太字にする技術は持ち主が自己紹介の文で選べるので、黒い単色のアイコンの技術を太字にしなければ問題は起きない。
- 技術ごとのダーク用のアイコン・反転の要否の設定（スキーマの変更）。
- 使用技術のデータの見直し（表示名の大文字小文字、Tools の件数、トップに表示するかの選び直し）。持ち主が A7 で直すもので、コードの変更は要らない。
- 頭文字の丸（アイコンが無い・読み込めない技術）。画像ではなくトークンの色で描いているので、今のままで両方のテーマで見える。

## 実装アプローチ

- 白黒反転: CSS の `invert` をダークモード（Panda の `_dark`）のときだけ足す。グレースケールにした後なので、反転しても色相は変わらず、明るさだけが逆になる。
- トーンカーブ: CSS の `filter` の関数（`brightness`・`contrast`）は、黒と白の両方を動かさずに中間だけを濃くできない（`brightness` は白も暗くし、TS・JS・Ps のような地の塗られたアイコンの白い文字が沈む。`contrast` は薄いグレーをさらに薄くする）。そこで SVG の `feComponentTransfer` の `gamma`（指数 1 より大きい値）で、0 と 1 を動かさずに中間を濃くする。グレースケールも同じ SVG フィルターの `feColorMatrix`（`saturate` 0）で行い、CSS からは `filter: url(#…)`（ダークは後ろに `invert`）で参照する。
- 指数の値: 実装のときに P1 の Tech Stack（デモデータと、持ち主の本番相当のデータのスクリーンショットにある React・Node.js・Firebase・sharepoint）を見て決める。基準は、ライトで React・Node.js の形が地から読み取れ、TS・JS・Ps の地の塗られたアイコンの文字が潰れないこと。決めた値は「実装時に決めた細部」に書く。
- Panda での書き方: `filter` に `url()` を含む値を、固定した版の Panda（strictTokens・strictPropertyValues）で書けるかを型定義で確かめる。書けなければ Panda の任意の値の書き方を型定義で確かめて使う。今の `filter: 'auto'` と `grayscale` のユーティリティは使わなくなる。
- SVG フィルターの置き場: `SiteChrome` の中に、大きさ 0 で `aria-hidden` の `<svg>` を1つ置き、`<filter>` に固定の ID を付ける。使用技術のアイコンを出すのは公開側の `$lang` の下の画面だけで、どれも `SiteChrome` の中にある。`SiteChrome` は二重に出さない作り（SDD 4.1）なので、ID も重ならない。`color-interpolation-filters="sRGB"` を付け、CSS のグレースケールと同じ色空間で計算する。
- ↗: `StackChipItem` に ↗ を見せないかの引数を足す。見せないときも `ExternalMark` の読み上げの文（`messages.label.opensInNewTab`）は残す。リンクであることはホバーの下線（今の `chip` のレシピ）で示す。

採らなかった案:

- アイコンの下に明るい台を敷く: どのアイコンも見えるが、ダークで白い四角が並んで目立ち、「枠を付けない」方針（design-spec 4.4）と逆になる。
- 技術ごとのダーク用の指定（A7 のスイッチかダーク用のアイコンの欄）: アイコンごとに正確に直せるが、スキーマの変更と、アイコンごとに設定する手間がかかる。
- ダークで `invert` に `hue-rotate(180deg)` を足して色を残す: 公開側の使用技術のアイコンはグレースケールなので、色を残す必要がない。

## 詳細設計

### API変更

なし。

### UI変更

公開側の使用技術のアイコン（`StackIcon`）:

| テーマ | 処理（左からかける） |
|---|---|
| ライト | グレースケール → トーンカーブ（中間を濃く） |
| ダーク | グレースケール → トーンカーブ → 白黒反転 |

P1 の Tech Stack のチップ:

```
変更前: ⚛ React ↗   ◇ Next.js ↗   ▣ Vue
変更後: ⚛ React     ◇ Next.js     ▣ Vue      ← リンクのチップはホバーで下線
```

- リンクのチップは、読み上げで「React、別タブで開く」のように読ませる（今と同じ）。
- P2/P3 のチップ、作品・プロジェクトの広げた中の入口のリンクの ↗ は変えない。

反転しても見え方が崩れるアイコン（絵文字風の Emotion のように、写真や多色の絵を使ったもの）は、そのまま受け入れる。直したいときは、持ち主が A7 で単色のアイコンに差し替える。

### データマイグレーション

なし。

## テスト方針

| テスト種別 | 対象 |
|-----------|------|
| Unit | なし（スタイルとマークアップだけの変更） |
| Integration | なし |
| E2E | P1 の Tech Stack・行のアイコン・P2 の使用技術のアイコンが、ライトではトーンカーブの SVG フィルターを参照し、ダークではそれに `invert` が足されること（計算されたスタイルの `filter` で確かめる）。今の「グレースケールで切り抜かれない」の検査をこれに置き換える。自己紹介の太字の前と管理画面のアイコンには `filter` が無いこと（今の検査のまま）。P1 の Tech Stack のリンクのチップに ↗ の記号が見えず、読み上げの「別タブで開く」があること。P2 の使用技術のリンクのチップには ↗ が見えること |
| アクセシビリティ | 今の P1・P2 の axe の検査（ライト・ダーク）が通ること |
| 目視 | P1 の Tech Stack をライト・ダークで撮り、黒いアイコン（Next.js・vercel）と薄いアイコン（React・Node.js）が両方のテーマで地から読み取れること。iPhone の Safari でも、staging で SVG フィルターが効いていることを確かめる（E2E は Chromium だけのため） |

## ロールアウト計画

1. 実装を PR で `main` に入れる。`make lint`・`make typecheck`・`make test`・`make e2e` が通ること。
2. staging に昇格し、PC のブラウザと iPhone の Safari で、P1 の Tech Stack・行のアイコン・P2 をライト・ダークで確かめる。
3. 本番に昇格する。戻すときは昇格 PR を revert する（データの変更はないので、戻しても何も残らない）。

## 実装時に決めた細部

- トーンカーブの指数は 2。代表的な色のアイコン（黒の Next.js・vercel、水色の React、緑の Node.js、黄の Firebase、青地に白文字の TS、黄地に黒文字の JS、濃紺地に水色の文字の Ps、青地に白の Docker）を再現した検証ページで、グレースケールだけ・指数 1・1.5・2・2.5 をライト・ダークで撮って比べた。2 で React・Node.js・Firebase が地から読み取れ、TS の白い文字は変わらない。Ps の水色の文字はどの値でも少し沈み、2.5 では読みにくくなるので 2 で止めた。
- Panda 2.1.1 の `filter` の型は `none` と任意の値（`[...]`）だけを受けるので、`filter: '[url(#stack-icon-tone)]'`（ダークは `'[url(#stack-icon-tone) invert(1)]'`）と書く。生成される CSS が `filter: url(#stack-icon-tone)` ／ `filter: url(#stack-icon-tone) invert(1)` になることを `panda cssgen` で確かめた。
