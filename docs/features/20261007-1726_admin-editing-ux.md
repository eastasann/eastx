# Feature Design Doc — 管理画面の編集の UX 改善

> 原則: 1ユーザーストーリー = 1 Feature Design Doc
> 変更規模: 中（スキーマ・新しい画面なし。編集ビューのレイアウト L5・L6 と、design-spec 4.1・4.3・4.4・6.4・6.7 の振る舞いと見た目が変わる）
> 前提: `docs/features/20261007-1427_site-redesign.md` の実装が `main` に入っていること（共通のトークン（書体・本文の大きさ・リンクの色）をこの FDD でも使うため）。公開サイトの刷新はまだ本番に出ていないので、この FDD の実装と同じ昇格で一緒に出す（「ロールアウト計画」）

## 背景と目的

管理画面は初期実装のあと手が入っていない。持ち主が挙げた困りごとは「画面が見にくい・狭い」「書いて公開するまでの手数」「日英の入力が面倒」の3つ。ローカルの開発環境（デモデータ）で実際の画面を開き、コードも調べて、原因を次のように確かめた（2026-10-07）。

| 困りごと | 確かめた原因 | 根拠 |
|---|---|---|
| 画面が狭い | L5 は、操作バー → 基本項目（タイトル・概要・スラッグ・リンク・使用技術・サムネイル）→ エディタとプレビュー、の順に縦に積む。作品の編集ビューでは、高さ 840px の画面でエディタは最初の画面の下端に約 150px しか入らない | design-spec 6.7 の図、`src/admin/portfolio.tsx`・`posts.tsx`、`layouts.tsx` の `SplitEditLayout` |
| 画面が狭い | エディタとプレビューは、本文の長さだけ縦に伸びる。長い本文ではページ全体がスクロールし、保存のボタンを含む操作バーが画面の外へ消える | `layouts.tsx` の操作バーは固定されていない |
| 書いて公開するまでの手数 | Cmd/Ctrl+S が効かず、ブラウザの「ページを保存」が開く | `markdown-editor.tsx` の keymap は既定と履歴だけ |
| 書いて公開するまでの手数 | 保存していない変更があるかが画面に出ない | `editor.tsx` の未保存の判定は、移動のときの確認にしか使っていない |
| 書いて公開するまでの手数 | 隠れている言語タブの欄にエラーがあると、タブの印だけで、どの欄か分からない。送る前の入力チェックに引っかかっても、画面の外の欄のエラーには気づけない | `editor.tsx` の `SaveProblems`、言語タブ |
| 書いて公開するまでの手数 | 保存のボタンが押せないとき（スラッグの作成中・画像のアップロード中）に理由が出ない | `long-form.tsx` の `useBusy` |
| 書いて公開するまでの手数 | 使用技術を1つ選ぶたびに検索欄が閉じ、5つ付けるには「追加」から5回やり直す | `long-form.tsx` の `StackPicker` |
| 日英の入力 | 言語タブを替えると、タイトル・概要・エディタ・プレビューがまとめて替わる。日本語を見ながら英語を書けない | design-spec 6.7.1 の言語タブ |
| 書きかけを失う | 一時保存はログインの期限切れのときだけで、タブやブラウザが落ちると書きかけが消える | design-spec 6.4、`src/admin/backup.ts` |
| 画面が見にくい | 公開サイトは静かな見せ方（モノトーン、グレーの文字と濃い強調、枠の無い1行の行）に変わったが、管理画面は藍の塗りのボタン、藍の地のサイドメニューの現在地、枠付きの入力欄、大きな題、丸い大きなチップのまま。使用技術を8つ付けると、チップだけで2段・約130px を使う | 1440px 幅のデモデータの A5・A4 の編集ビュー、`src/ui/recipes.ts`・`src/admin/sidebar.tsx` |

目的: 管理画面の見た目を公開サイトと同じ静かなトーンに揃え、本文を書く場所を画面の主役にし、保存の操作と状態をいつでも見えるようにし、日英を並べて書けるようにし、書きかけを失わないようにする。PRD 5章の KPI「既存の項目を直して公開し直すまで1分以内」を、長い本文でも満たせるようにする。

## Goal / Non-Goal

### Goal

**レイアウト（L5: 作品・プロジェクト・ブログ・コーディング記録の編集ビュー）**

1. 操作バー（「操作バー」の表の要素）を画面の上に固定する。
2. 言語ごとの欄（「L5 の欄の置き場所」の表）をエディタの上に置き、共通の欄を右の設定パネルに移す。
3. デスクトップ・タブレット（≥768px）では、L5 を画面の高さに収め、エディタ・プレビュー・設定パネルをそれぞれの中でスクロールさせる。モバイル（<768px）はページ全体をスクロールさせ、操作バーだけを固定し、エディタは `size.editor`（400px）以上の高さにする（ソフトウェアキーボードで画面の高さが縮むため）。
4. 操作バーに表示の切り替え「書く｜並べる｜日英｜プレビュー」を置く。既定は「並べる」。表示ごとの中身は「表示の切り替え」の表のとおり。「並べる」では、プレビューがエディタのスクロールに追従する。
5. 編集ビューを開いているあいだ、デスクトップ（≥1024px）でも左のサイドメニューをアイコンだけに縮める。
6. 幅 1280px 未満では、設定パネルを右から開く引き出しにし、操作バーの「設定」ボタンで開く。設定パネルの欄に誤りがあれば、「設定」ボタンに印を付ける。
7. 操作バーの題は、日本語のタイトル、なければ英語のタイトル、どちらも無ければ「新規作成」（今と同じ規則を明文化する）。

**レイアウト（L6: プロフィール・経歴・使用技術の編集ビュー）**

8. Goal 1 の操作バーの固定と、Goal 10〜14 の保存の操作と状態、Goal 19〜21 の自動退避を入れる。
9. 日英の項目を持つ L6（プロフィール・経歴）に、表示の切り替え「片方｜日英」を置く。「日英」では言語ごとの欄を左右に並べ、言語タブを出さない。使用技術は日英の項目を持たないので切り替えを置かない。Markdown の欄（自己紹介・経歴の内容）は、今のテキストエリアと「入力｜プレビュー」の切り替えのまま。

**保存の操作と状態（L5・L6 共通）**

10. Cmd/Ctrl+S で、今の状態を変えない保存をする（「Cmd/Ctrl+S の割り当て」の表）。公開中の項目では「更新する」と同じで、保存した瞬間に公開サイトにも出る（持ち主の決定。ブログ・記録では design-spec 6.7.1 の条件で更新日も変わる）。
11. ボタンが押せないとき、理由を操作バーに短く出す（「保存しています」「スラッグを作っています」「画像をアップロードしています」）。
12. 操作バーに保存の状態を出す（「操作バー」の表）。
13. 保存しようとして誤りがあったら、最初の誤りの欄へスクロールしてフォーカスを移し、誤りの件数をトーストでも出す（「誤りの欄への移動」）。
14. 画像欄（サムネイル・写真・技術アイコン）のアップロード中も、保存のボタンと Cmd/Ctrl+S を止める（今は本文エディタのアップロード中だけ）。

**入力の手数**

15. 使用技術の検索欄は、選んでも閉じずに続けて選べる。選んだ技術は候補に「✓」を付け、もう一度選ぶと外す。Escape か欄の外を押すと閉じる。
16. 上限のある欄（タイトル・名前・所属・場所・肩書き・表示名 200字、概要 500字）に、文字数が上限の8割を超えたら「n / 上限」を出す（200字の欄は 161字から、500字の欄は 401字から）。上限を超えたら赤字にする。入力は止めない（保存のときに今の入力チェックで止まる）。数え方は Zod の `max` と同じ（JavaScript の文字列の長さ）。
17. エディタの下に「画像を挿入」ボタンを置き、ファイルを選んでアップロードできるようにする（今の貼り付け・ドロップと同じ処理。キーボードだけでも画像を入れられるようにするため）。
18. エディタで Cmd/Ctrl+F の検索（CodeMirror の検索の keymap）を使えるようにする。

**作業の保全**

19. 保存していない変更があるあいだ、フォームの値が変わって1秒たったら、localStorage に退避する（「自動退避の規則」）。
20. 編集ビューを開いたとき、退避した内容が今のサーバーの内容と違えば、今の復元の提案に退避した時刻を添えて出す。サーバーの最終保存の方が新しければ、その旨も添える。
21. ログアウトに成功したら、退避（`eastx:backup:*`）をすべて消す。

**その他**

22. サムネイルの画像欄のプレビューを、公開側と同じ縦横比（`aspectRatios.thumbnail`、16:9）の切り抜き（cover）で出す（今は全体を縮めて出していて、公開側でどこが切れるか分からない）。
23. 読み込み中の L5 を L5 の形のスケルトンで描く（今は L6 の形で描いてから L5 に切り替わり、レイアウトが跳ぶ）。
24. 作品・プロジェクトの編集ビューと、ブログ・コーディング記録の編集ビューの L5 の骨組みを、1つの部品にまとめる（Goal 1〜7 を2か所に書かないため）。

**見た目（「見た目」の節）**

25. 管理画面の一番の操作のボタン（`button` の `solid`）を、藍ではなく濃い無彩色の塗りにする。アクセント（藍）は、フォーカスの輪・今の言語（言語タブ・公開側のヘッダー）・ページングの現在位置にだけ使う。ボタンの色は新しいトークン `color.action.*` で持つ。
26. サイドメニューの地の色をやめ（地は `bg.canvas`、右の区切り線は残す）、項目をグレーの文字、現在地を濃い文字と太字にする。戻るリンクもグレーにする。
27. 状態の札（下書き・公開）を、地の無い文字と小さな丸にする（公開は濃い文字と `success.default` の丸、下書きはグレーの文字と丸）。一覧ビュー（L4）の札も同じ部品なので同じに変わる。
28. 入力欄のラベルを小さなグレーの文字にする（L5・L6 の全部の欄）。
29. L5 の言語ごとの欄（タイトル・概要）を枠の無い入力にする。タイトルは `heading-3` の大きさ、概要はグレーの `body-sm`。空のときは欄の名前を placeholder に出し、見えるラベルは置かない（読み上げの名前は `aria-label`）。ホバー・フォーカスで下に細い線を出し、誤りがあれば下の線を赤にして、欄の下に理由を出す。設定パネルの欄は今の枠（`border.default`）のまま。
30. 選んだ使用技術を、枠の無い「並べ替えの取っ手・小さなアイコン・表示名・×」の項目にし、横に並べて折り返す（チップ1つで1行にはしない。縦に伸ばさないため）。
31. 操作バーの題を `heading-3` の大きさにする（今の `heading-1` は操作バーを固定すると高さを取りすぎるため）。

### Non-Goal

持ち主と範囲を合わせた結果、今回は入れない。理由と、入れるときの扱いを書く。

- 公開中の中身を下書きで直す（公開版と別に作業中の版を持つ）: 全種類のテーブル・CMS API・公開の状態の遷移（SDD 5.3）が変わる大きな変更なので、要るなら別の FDD にする。今回は自動退避で、書きかけを失う危険だけを減らす。
- 公開前の確認（編集ビューから公開ページを開く導線、カードやタイトルの見え方のプレビュー、下書きのプレビュー URL）: 持ち主が今回の範囲から外した。
- 日本語だけの記事のスラッグの自動の作り方: 持ち主が今回の範囲から外した。今どおり、英語のタイトルが無ければ公開のときに入力を求める。
- サーバーへの下書きの自動保存: 途中の状態が入力チェックに引っかかる場合の扱いと、「最終保存日」が動き続ける問題があり、ブラウザへの退避を選んだ。
- L6 の Markdown の欄を CodeMirror にする: 欄が短く、効果が小さい。
- 同じ項目を複数のタブ・端末で開いたときの退避の衝突と、同時編集の検出: 同時編集は SDD 1章の Non-Goal。同じキーの退避は、後から書いた方が残る。
- 公開日を、公開する前に入れられるようにする（SDD 5.9 の制約）、ダッシュボードの近道や最近の更新の一覧、使用技術の一覧での「トップに表示」の切り替え、並べ替えの「先頭へ」の操作: 今回の困りごと（狭い・手数・日英）と関係が薄い。
- 管理画面の画面移動のたびのセッションの確認（SDD 5.1 の設計どおりの動き）: 今回の困りごとの原因ではない。
- 一覧ビュー（L4）とダッシュボード（A2）のレイアウトの変更。共通の部品（ボタン・状態の札・サイドメニュー）の見た目の変化（Goal 25〜27）だけは、L4・A2・A1・ダイアログにも同じに効く。
- CMS API・DB スキーマの変更。公開側の描画の結果の変更。

## 実装アプローチ

### L5 の骨組み

- `SplitEditLayout` を作り直し、作品・プロジェクト・ブログ・記録が同じ部品を使う。部品が受け取るのは、言語ごとの欄を描く関数（言語を引数に取る）、本文のエディタを描く関数、設定パネルの中身、操作バーのボタン。言語ごとの欄とエディタを関数で受け取るのは、「日英」で2つの言語ぶんを並べて描くため。
- 高さ（≥768px）: ページ全体のスクロールをやめ、L5 を画面の高さ（Panda の `h: 'dvh'`。`src/ui/dialog.tsx`・`src/admin/layouts.tsx` が今も使う値で、ADR-014 のトークンの決まりの中にある）に収める。操作バーと言語ごとの欄の高さを除いた残りをエディタとプレビューに割り当てる。
- フォームの状態は今のまま（日英の両方を1つのフォームに持つ。ADR-008）。表示の切り替えは見せ方を変えるだけで、状態は持ち替えない。「日英」では、言語ごとに CodeMirror の `EditorView` を1つずつ作る。
- 表示の切り替えの記憶: localStorage の `eastx:admin:editor-view`（`write`・`split`・`bilingual`・`preview`）と、L6 用の `eastx:admin:form-view`（`single`・`bilingual`）。全種類で共通の1つの値。管理画面は SSR しない（`ssr: false`）ので、Cookie にする理由が無い。読めない値は既定（`split`・`single`）。値を書くのは、持ち主が切り替えを押したときだけ。幅のせいで使えない表示（モバイルの `split`）は `write` として描くが、覚えた値は書き換えない。幅が変わったら、覚えた値から描き直す。

### 表示の切り替え

| 表示 | 言語ごとの欄 | エディタ | プレビュー | 言語タブ |
|---|---|---|---|---|
| 書く | 選んだ言語 | 選んだ言語、幅いっぱい | なし | あり |
| 並べる | 選んだ言語 | 選んだ言語、左 | 選んだ言語、右（追従） | あり |
| 日英 | 日本語（左）と英語（右） | 日本語（左）と英語（右） | なし | なし（言語の見出しに「言語あり」の印） |
| プレビュー | 選んだ言語（読むだけでなく編集もできる） | なし | 選んだ言語、幅いっぱい | あり |

- 「日英」から他の表示に戻ったら、「日英」にする前に選んでいた言語タブに戻す。
- L6 の「片方」は今の言語タブ、「日英」は言語ごとの欄を左右に並べてタブを出さない。<768px の「日英」は縦に積む（L5 も同じ）。

### L5 の欄の置き場所

| 種類 | 言語ごとの欄（エディタの上） | 設定パネル |
|---|---|---|
| 作品 | タイトル、概要 | スラッグ、外部リンク、GitHub、使用技術、サムネイル |
| プロジェクト | タイトル、概要 | スラッグ、開始年月・終了年月、外部リンク、使用技術、サムネイル |
| ブログ | タイトル | スラッグ、公開日、サムネイル |
| コーディング記録 | タイトル | スラッグ、種類、公開日、参考リンク、サムネイル |

公開日は、今と同じく一度も公開していない項目では入力できない状態で出す（SDD 5.9）。

### Cmd/Ctrl+S の割り当て

| 種類 | 新規作成（まだ保存していない） | 下書き | 公開中 | 状態を持たない |
|---|---|---|---|---|
| 作品・プロジェクト・ブログ・記録・経歴 | 下書き保存（作成して URL を `/{id}` に置き換える。今の初めての保存と同じ） | 下書き保存 | 更新する | 対象外 |
| プロフィール | 対象外 | 対象外 | 対象外 | 保存 |
| 使用技術 | 保存（作成） | 対象外 | 対象外 | 保存 |

- 保存していない変更が無いときは、何も送らない（`updatedAt` を進めない）。ブラウザの「ページを保存」は止める。
- 押せないとき（保存中・スラッグの作成中・アップロード中、新規作成で入力が空）は何も送らず、ブラウザの「ページを保存」も止める。
- 編集ビューの最上位で `keydown` を受け、`(metaKey || ctrlKey) && key === 's'` で `preventDefault` してから上の表のとおりに保存する。CodeMirror の keymap では `Mod-s` の既定の動きを止めるだけにし、処理は最上位に任せる。
- IME の変換中（`event.isComposing`）は無視する。
- モーダルの確認ダイアログ（削除・非公開に戻す・スラッグの変更・移動の確認）が開いているあいだは、ブラウザの「ページを保存」を止めるだけで保存しない。設定の引き出しと使用技術の検索欄の中では保存する（検索欄は開いたまま）。

### 誤りの欄への移動

- 対象: 送る前の入力チェック（Zod・公開のルール）の誤りと、サーバーから返った `INPUT_VALIDATION_FAILED` の `fieldErrors`、`PUBLISH_REQUIREMENTS_NOT_MET` の `missing`、`SLUG_CONFLICT`。
- 「最初の誤り」の順: 言語ごとの欄（日本語 → 英語。各言語の中は画面の上から）→ 本文（日本語 → 英語）→ 設定パネルの欄（画面の上から）。
- 移る先が隠れた言語タブの中なら、そのタブに切り替える。設定の引き出しの中なら、引き出しを開く。「日英」の表示では、両方の言語が見えているのでタブは替えない。

### 自動退避の規則

退避の形は今の一時保存と同じ。キーは `eastx:backup:{種類}:{id か new}`（種類は `profile`・`career`・`stack`・`work`・`project`・`blog-post`・`coding-log`、プロフィールは行の `id`、まだ無ければ `new`）、値は `{ savedAt: ISO 8601 の文字列（ブラウザの時計）, values: フォームの状態 }`。

| 場面 | 退避の扱い |
|---|---|
| 編集ビューを開いた直後（持ち主がまだ何も入力していない） | 書きも消しもしない |
| 復元の提案を出しているあいだ | 書きも消しもしない。「復元する」を押したら、復元した値を最初の退避として扱う |
| 入力した（値が変わった） | 1秒のデバウンスのあと、今の値と比べる元（下の行）が違えば書く。同じなら消す |
| 比べる元 | 既存の項目は最後に読んだ・保存したサーバーの内容。新規作成は空のフォームの初期値。比べ方は今の `sameValues`（フォームの状態を深く比べる） |
| 保存に成功した | 送った値と今のフォームの値が同じなら消す。保存の通信中にさらに入力して違っていれば、今の値で書き直す |
| 新規作成で初めて保存した | `new` のキーを消す（上の行と同じ条件）。以後は `{id}` のキー |
| 削除した | その項目のキーを消す |
| 「保存していない変更があります。移動しますか？」で移動を選んだ | 消す |
| ログインの期限切れ（`UNAUTHORIZED`）で A1 へ移す | 最新の値をデバウンスを待たずに書き、確認を出さずに移す。消さない |
| ブラウザ・タブを閉じた、落ちた | 残る（次に開いたときに提案する） |
| ログアウトに成功した | `eastx:backup:` で始まるキーをすべて消す |

- 復元の提案: 退避があり、その `values` が比べる元と違えば、「一時保存した内容があります（10月7日 14:32）［復元する］［破棄する］」を出す。既存の項目で、サーバーの `updatedAt` が退避の `savedAt` より新しければ、2行目に「保存済みの内容の方が新しくなっています」を添える。時刻の比べ方は、ブラウザとサーバーの時計のずれを許す（管理者1人がふだん同じ端末で使うため）。同じなら提案せずに消す。
- IME の変換中に値が変われば、その値も退避されうる。復元すると未確定だった文字が確定した文字として入るだけなので、変換中を区別しない。

公開サイトと同じ静かなトーンにする。色は白・黒・グレーで、強調は濃い文字と太さでつける。面は地の色で分けず、細い区切り線で分ける。

### プレビューのスクロールの追従

- `renderMarkdown` のオプション（`sourceLines: true`）で、ブロックの要素に元の行番号の `data-source-line` を付ける。付けるのは rehype-sanitize の後（GitHub のスキーマは `data-*` を消すため）。公開側のサーバーの描画はこのオプションを使わないので、公開側の HTML・Cache API のキー・`RENDER_VERSION` は変わらない。管理画面のプレビューはブラウザで描き、Cache API を通らない。
- エディタの見えている先頭の行に最も近い `data-source-line` のブロックへ、プレビューをスクロールする。追従はエディタ → プレビューの一方向だけ（両方向にすると互いに動かし合って揺れるため）。

- ロールバック: 古いコードは、退避をサーバーの内容と比べずに復元を提案する。自動退避で増えた古い退避を「復元する」と、サーバーにある新しい内容を古い内容で上書きしうる。そのため、戻す前に、持ち主が管理画面を開いているブラウザの開発者ツールで `eastx:backup:` で始まるキーを消す（残したい書きかけがあれば、先に保存する）。

## ロールアウト計画

1. 前提を確かめる: 実装のコミットの祖先に `docs/features/20261007-1427_site-redesign.md` の実装（29e95ec）があること。本番はまだ刷新の前（f78219e）なので、この昇格で公開サイトの刷新も一緒に出る。staging と本番の確認に、刷新の FDD の「ロールアウト計画」の確認も含める。
2. 実装を PR で `main` に入れる。`make lint`・`make typecheck`・`make test`・`make e2e` が通ること。
3. staging に出す前に、リリースの前から残る一時保存を用意する: staging の管理画面で経歴を1つ開き、開発者ツールで `eastx:backup:career:{その id}` に、今の形（`{ savedAt, values }`。`values` はその経歴のフォームの状態のタイトルだけを変えたもの）の値を入れる。
4. `make promote ENV=staging` で staging に出す。staging の管理画面で次を確かめる:
   - 3 で入れた経歴の一時保存が、復元の提案に時刻付きで出る。
   - ブログの下書きを1つ作り、長い本文を書く → スクロールしても操作バーが見える → Cmd+S で「保存済み」と時刻が出る。
   - 「日英」で英語の本文を足して Cmd+S。
   - 保存せずに入力して再読み込みすると復元の提案が出る。提案に答えずにもう一度再読み込みしても、提案が出続ける（退避が消えていない）。
   - ブラウザの幅を 1200px にして、設定の引き出しからスラッグを直せる。
   - 経歴（L6）の「日英」で両方を書いて保存できる。
   - 後始末: 作ったブログの下書きを削除し、開発者ツールで `eastx:backup:` で始まるキーが残っていないことを確かめる（残っていれば消す）。
5. 同じ SHA を `make promote ENV=production` で本番に出す（`docs/04_deployment-procedure.md`）。本番の管理画面で既存のブログを1つ開き、何も変えずに Cmd+S を押して「保存済み」のまま（何も送られない）こと、サイドメニューと設定パネルの配置を確かめる。
6. 戻すときは、データマイグレーションの節のとおり退避を消してから、昇格 PR を revert する。revert で戻る先の SHA に site-redesign の実装が含まれるかを1と同じ方法で確かめ、含まれなければ、公開サイトも刷新の前に戻ることを承知のうえで行う。

## 実装時に決めた細部

設計の不備ではない細部の判断で、上の記述から変わったもの・足したもの。

- トークン: 「トークン」の表に `radius.none`（枠の無い欄の角）、`typography.ui-strong`（サイドメニューの現在地の太さ）、`z-index.toolbar`（固定の操作バー）を足した。どれも既存のプリミティブを指すだけで、値は増やしていない。
- 誤りの件数の通知の文言は「確かめる項目があります（{件数}件）」。件数は誤りの欄の数と、欄に結びつかない理由の数の和。
- 復元の提案の時刻は、保存の状態と同じ書き方にした（今日なら「14:32」、それ以外は「10月6日 14:32」）。
- プロフィールの退避をサーバーの内容と比べるときは、SNS リンクの並べ替えの目印の ID を外して比べる。ID は開くたびに作り直すので、比べると開き直すたびに退避が違って見える。
- 英語のタイトルが空のときは、スラッグの追従は作る値（空）が決まっているので、API を待たずに入れ、保存を待たせない。保存の直後（項目の ID が決まって追従をやり直すとき）に、Cmd/Ctrl+S が「スラッグを作っています」で止まらないようにするため。
- モバイル幅の操作バーは、戻るリンクと「設定」ボタンをアイコンだけにする（読み上げの名前は残す）。固定の操作バーが画面の高さを取りすぎないため。
- 状態の札と「未保存の変更」の丸は疑似要素で描き、札の文字（読み上げ）には入れない。
- 選んだ使用技術の並べ替えのつまみと「×」は、押せる大きさを 24px に保った小さなボタンにした（ボタンのレシピの `compact`）。並べ替えの項目の地は、持ち上げているあいだだけ付ける。
- CodeMirror の入力の要素に `tabindex="0"` を付けた。エディタの中でスクロールする枠を、axe が「キーボードで届かないスクロール領域」（`scrollable-region-focusable`）と判定するため。
- 復元の提案を出しているあいだは、保存しても期限が切れても提案した退避を消さない（「自動退避の規則」の表の「書きも消しもしない」を、保存と期限切れにも当てはめた）。「破棄する」では、提案のあいだに入力した値があれば、その値で書き直す。
- ログアウトに成功したら、退避を消したうえで、ログイン画面へ移るまで退避を書かない。ログアウトの応答を待つあいだに、入力から1秒の待ちが終わって書き戻すのを防ぐため。
- localStorage を使えない・容量の上限で書けないときは、退避なしで編集を続ける。
- Cmd/Ctrl+S は Caps Lock 中（key が大文字）も受け付け、Shift・Alt 付きは受け付けない。
- 画像欄のアップロードは、設定パネルが幅 1280px をまたいで描き直されても続くので、保存を待たせるのは欄の state ではなく、アップロードの前後で直接知らせる。
- 誤りの欄へ移るために設定の引き出しを開いたときは、引き出しの最初のフォーカスをその欄にする（引き出しの既定のフォーカスと競わないため）。
- アクセントを使う場所を「フォーカスの輪・ページングの現在位置・今の言語」に揃えるため、オンのスイッチを `action` の塗りに、選択肢の選んだ印・メニューの今いる項目・一覧とダッシュボードのリンクのホバーを濃い文字・太さ・下線にした。セレクトと使用技術の検索の欄のラベルもグレーにした。
- 768px 以上の L5 でも、通知が多く画面が低いときはエディタの最小の高さ（`size.editor`）を保ち、言語ごとの欄とエディタの列ごとスクロールする。
- 手元での確認で持ち主が決めた: 表示の切り替え（書く｜並べる｜日英｜プレビュー、片方｜日英）と「削除」はアイコンだけにし、名前はツールチップと読み上げで伝える。保存・公開の操作は文字のまま。使用技術の検索の候補にも技術のアイコンを出す。
- 選んだ使用技術の並べ替え（横に並べて折り返す並び）の当たり判定は、重なっている項目のうち左上の角が最も近いものを選び、どれにも重ならないときだけ中心の近さで選ぶ。幅の違う項目が複数の行にわたると、中心の近さや重なりの大きさだけでは、矢印キーで動かしても元の位置や行き先の隣の項目が選ばれ、キーボードで並べ替えられなかった。
