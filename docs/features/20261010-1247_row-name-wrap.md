# Feature Design Doc — 広げた行の名前を区切りで折り返し、続きを ▸ の左端から始める

> 原則: 1ユーザーストーリー = 1 Feature Design Doc
> 変更規模: 小（既存の画面 P1 の行の描き方の修正。API・スキーマの変更なし）

## 背景と目的

P1 の経歴・作品・プロジェクトの行は、広げると1行目の名前を「…」で切らずに折り返して全文を出す。折り返した続きは、▸ の幅の分だけ右（名前の開始位置）から始まる（design-spec 6.1.3）。持ち主がモバイル幅（360px）で実際の経歴を広げて、次の2点を問題にした（2026-10-10）。

- 折り返す位置: `Accenture in the Philippines ~ Packaged Application Development Senior Analyst` は、タイトルの途中で折り返し、`Packaged` だけが1行目に残る。所属とタイトルの境が読み取りにくい。
- 左端の段: 名前の続きは ▸ の右から、その下の期間と広げた中は ▸ の左端から始まる。左端が2か所あり、段が付いて見える。左端を ▸ の左端に揃える決まりは、前回の変更（`docs/features/20261008-2043_top-row-expand.md`）で2行目と広げた中に入れたが、名前の続きは対象の外だった。

持ち主が決めたこと（2026-10-10）:

- 経歴の名前は、`所属 ~` と `タイトル` の境で折り返すことを優先する。`~` は所属の側に残す。
- 名前の続きの行は、期間・広げた中と同じく ▸ の左端から始める。作品・プロジェクトの行も同じ決まりにする。

## Goal / Non-Goal

### Goal

1. 広げた経歴の行で、`所属 ~ タイトル` が1行に収まらないときは、タイトルを丸ごと次の行から始める。タイトルが1行に収まらないときだけ、タイトルの中で折り返す。所属が1行に収まらないときも、所属の中で折り返す。
2. 広げた経歴・作品・プロジェクトの行で、名前の2行目からは ▸ の左端から始める。1行目の名前の開始位置は閉じた行と同じ（▸ の右）で、広げても横に動かない。
3. 経歴の期間（デスクトップ幅は右、モバイル幅は2行目）と、▸ を1行目の先頭の行の高さに揃える決まりは今のまま。

### Non-Goal

- 閉じた行の見え方（1行で「…」で切る）の変更。
- ブログ・コーディング記録の行の変更（広げず、1行で「…」で切る）。
- 作品・プロジェクトのタイトルの中の折り返す位置の指定（区切りになる `~` を持たないので、ブラウザの折り返しに任せる）。
- 和文の語の途中で折り返さないための処理（`word-break: keep-all` や分かち書き）。和文の所属・タイトルは、それぞれの中では今どおり文字の境で折り返す。
- API・DB・公開側のサーバー関数・辞書・デザイントークンの変更。

## 実装アプローチ

今の行の頭（`rowHead`）は、▸・名前・右のメタを3列の格子（`toggle main meta`）に置く。名前は2列目にあるので、折り返した続きも2列目の左端（▸ の右）から始まる。続きを ▸ の左端から始めるには、▸ を名前と同じ文の流れに入れる必要がある。

- 広げたときだけ、格子の領域を `"main main meta"`（モバイル幅の経歴は `"main main" "meta meta"`）にし、名前の領域が ▸ の列にまたがるようにする。▸ は名前の前に行内の要素として置き、右の余白を今の列の間隔と同じ `inline` にする。1行目の名前の開始位置は閉じた行と同じになり、続きの行は ▸ の左端（行の左の余白 `inset-dense` の位置）から始まる。閉じた行の格子は変えない。
- ▸ を1行目の先頭の行の高さに揃える箱（`firstLineBox`）は、行内に置いても同じく使う（本文の1行の高さを持ち、中身を上下の中央に置く）。
- 経歴の名前は、タイトルだけを `inline-block` の塊にし、`所属 ~` との間に空白を置く。`inline-block` の塊は残りの幅に収まらなければ丸ごと次の行へ移り、行の幅より長いときだけ塊の中で折り返す（塊の幅が行の幅で止まるため）。塊の中で折り返した続きも塊の左端、つまり ▸ の左端から始まる。所属は塊にせず ▸ の後ろから流す（所属まで塊にすると、所属が1行目の残りの幅に収まらないとき ▸ だけが1行目に残る）。`~` は所属の末尾に置き、`~` の前の空白は改行しない空白にする（普通の空白だと、所属の最後の行の残りが足りないとき `~` だけが次の行の頭に来る）。`~` とタイトルのグレーの色は今どおり。所属が無い経歴と、作品・プロジェクトの名前は、塊に分けない。
- 言語ラベルはタイトルの塊の後ろに置く（今どおり名前の続き）。
- ボタンの読み上げ名は今どおり名前の要素（`aria-labelledby`）だけで、▸ は `aria-hidden`。塊に分けても名前の要素の中身は変わらないので、読み上げ名は今と同じ `所属 ~ タイトル`。

採らなかった案:

- 名前の続きの行に負の字下げ（`text-indent`）をかけ、2列目から左へはみ出させる: 格子の列をはみ出して描くことになり、ボタンのフォーカスの枠・ホバーの地との関係が崩れる。トークンに負の値も無い。
- 広げたときに所属とタイトルを常に別の行にする: 1行に収まる短い経歴まで2行になり、閉じた行との違いが大きくなる。

## ロールアウト計画

1. 実装を PR で `main` に入れる。`make lint`・`make typecheck`・`make test`・`make e2e` が通ること。
2. staging に昇格し、スマホ（iPhone の Safari）と PC のブラウザで、P1 の経歴・作品を広げて確かめる。
3. 本番に昇格する。戻すときは昇格 PR を revert する（データの変更はないので、戻しても何も残らない）。
