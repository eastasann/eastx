# eastx — 設計仕様書

> **個人のレジュメ／ポートフォリオサイト eastasian を、「自作CMS＋フロント」の構成のまま作り直し、ブログやコーディング記録も載せられる場所にする。**

入力: `docs/concept.md`（Phase 0）、`docs/brainstorm-notes.md`（Phase 1）
画面遷移図: `docs/screen_flow.mermaid`（別紙）

## 1. プロダクト概要

### 1.1 コンセプト

今のサイト eastasian（https://eastasian.vercel.app/）は、日英を切り替えられる1ページのレジュメで、自作のCMS（管理画面＋API）で中身を更新している。これを、見せ方を刷新し、ブログとコーディング記録も載せられる形で作り直す。今の課題・目的・ターゲットは `docs/01_prd.md` の2・3章が持つ。

画面の設計で目指す体験は次のとおり。

- 訪問者は、トップを見てすぐに、何ができる人で、どんな経歴かがわかる
- 作品・プロジェクトを掘り下げて実力を確かめられ、信頼できる
- ブログやコーディング記録から、考え方や興味といった人となりが伝わる
- すべての中身を日本語と英語の両方で読める
- 持ち主は、自作のCMSから手間をかけずに中身を更新できる

### 1.2 プロダクト方針

| 項目 | 方針 |
|---|---|
| 用途・スコープ | `docs/01_prd.md` の2章 |
| 構成 | 「公開サイト（フロント）」と「管理画面（CMS）」に分ける。CMSは自作する |
| 対応言語（公開側） | 日本語と英語の2言語（i18nあり）。URLを `/ja` と `/en` で分ける。詳細は 1.4 |
| 対応言語（管理側） | 日本語のみ（使うのは持ち主1人のため）。入力する中身は日英の両方 |
| 対応デバイス（公開側） | スマホとPCの両方。どの画面幅でも同じ1列のレイアウトにする |
| 対応デバイス（管理側） | PC優先。スマホでも崩れずに使える程度に対応する |
| データ移行 | 今の公開サイトから中身を抽出し、新しいデータ構造に移す（9章） |

### 1.3 UI設計原則

| 原則 | 内容 |
|---|---|
| 1ページで伝わる | 公開側は、トップの1ページだけで何者かがわかるようにする。レジュメ・作品・プロジェクト・ブログ・コーディング記録の一覧は、独立した画面にせず、トップのセクションとして持つ |
| 移るのは詳細だけ | 別ページに移るのは、詳細（作品詳細、プロジェクト詳細、ブログ記事、コーディング記録詳細）を見るときだけ。それ以外の操作（セクション間の移動、セクションの次の10件を見る、経歴・作品・プロジェクトの行を広げる、テーマの切り替え）ではページを移らない。例外として、言語の切り替えは、同じ画面をもう一方の言語のURLで開き直す（1.4） |
| セクション内ページング | 件数が多いセクションは、項目を縦に10件まで積んで1ページとし、次の10件へは横にページングする。ページ（URL）は移らない（6.1.3） |
| 詳細は任意 | 作品・プロジェクトは、詳細本文を書いたものだけが詳細ページを持つ。詳細のないものは、行を広げた中の外部リンク・GitHub から進む |
| 見た目は差し替えられるように | 装飾は最小限にし、色・文字・角丸・余白などの見た目はすべてデザイントークン経由で指定する。あとからトーンを変えるときは、トークンの差し替えで済むようにする |
| 日英は同じ扱い | どの画面も、日本語と英語で同じ構成・同じ情報量で見せる。片方の言語しかない中身は、もう片方の言語で出して注記する |
| 管理画面は一覧性 | 管理画面は持ち主しか使わないので、余白より一覧性と操作の速さを優先する |

### 1.4 言語（i18n）の仕様

| 項目 | 仕様 |
|---|---|
| URL | すべての公開ページを `/ja/...` と `/en/...` の2系統で持つ。例: `/ja/works/my-app` と `/en/works/my-app`。スラッグ（URLの末尾）は日英で共通 |
| ルート `/` を開いたとき | 以前に選んだ言語があればその言語へ、なければブラウザの言語が日本語なら `/ja`、それ以外は `/en` へリダイレクトする |
| 言語の切り替え | ヘッダーの「JA ｜ EN」で切り替える。同じ画面を、URLの言語の部分だけを変えて開き直す。切り替えた先はページの一番上から始まり、トップの各セクションのページングは1ページ目に戻る。選んだ言語は覚えておき、次回のルート `/` の振り分けに使う |
| 言語ありの判定 | 中身ごとに、その言語で「言語あり」かを判定する。ブログ・コーディング記録はタイトルと本文の両方、プロフィールは名前、それ以外（経歴・作品・プロジェクト）はタイトルが入っていれば「言語あり」 |
| 片方の言語しかない中身 | 表示中の言語で「言語あり」でない中身は、もう片方の言語で出し、「この記事は日本語のみです」／「This post is available in Japanese only.」のような注記を添える。トップの行にも小さな言語ラベルを付ける（/ja で英語だけの中身には「英語のみ」、/en で日本語だけの中身には「Japanese only」）。プロフィールだけは例外で、注記もラベルも出さず、項目単位の代替表示だけで出す |
| 項目単位の代替表示 | 「言語あり」の中身でも、個々の項目（概要・所属・場所・肩書き・自己紹介など）が表示中の言語で空なら、その項目だけもう片方の言語の値を出す（注記は出さない）。どちらの言語も空なら、その項目ごと出さない。プロフィールは名前も含めて、この項目単位の代替表示だけで出す（プロフィールの「言語あり」の判定は、管理画面の言語タブの印にだけ使う） |
| 詳細本文だけ片方の言語 | 作品・プロジェクトで、タイトルは日英あるが詳細本文が片方の言語だけのとき、トップの行には言語ラベルを付けない。詳細ページでは、もう片方の言語の本文を出して注記する（6.2.3） |
| UIの文言 | ボタン・見出し・注記などの固定文言は、日英の辞書で持つ。主な対訳は次の表 |
| 日付の表記 | 公開側の日本語: `2026年9月`、`2026年9月12日`、期間は `2024年4月 – 現在`。公開側の英語: `Sep 2026`、`Sep 12, 2026`、期間は `Apr 2024 – Present`。管理側: `2026/09/12`（年月だけの項目は `2026/09`） |
| タイムゾーン | 日付と日時の表示は、すべて日本時間（Asia/Tokyo）で行う |
| ブラウザの言語の判定 | ブラウザが最優先にしている言語が日本語（`ja` で始まる）なら日本語とする |
| 選んだ言語の覚え方 | ルート `/` の振り分けに使えるよう、Cookie に覚える |
| ページの言語の宣言 | ページの言語（`lang`）はURLの言語にする。もう片方の言語の本文を出している部分には、その部分の言語を指定する。/ja のページでも、セクションの名前（見出し・戻るリンク・ページングと使用技術の並びの読み上げの名前）には英語を指定して英語の発音で読ませる。各ページに、もう片方の言語のURLを代替ページとして示す |
| セクションの名前 | 日英共通の英語にする: Career（経歴）、Projects（仕事で作ったプロジェクト）、Lab（個人で作った作品）、Tech Stack（使用技術）、Blog（ブログ）、Coding Log（コーディング記録）。公開側の P1 の見出し・ページングの読み上げの名前・詳細ページの戻るリンクと、管理画面の種類の名前（サイドメニュー・一覧ビューの題とテーブルの読み上げの名前（Lab の一覧）・編集ビューの題と戻るリンク・ダッシュボード）に使う。このドキュメントと System Design Doc は、概念を「作品」「プロジェクト」などと呼ぶ |

主な固定文言の対訳:

| 日本語 | 英語 |
|---|---|
| プロフィール | Profile |
| 職歴 ／ 学歴 | Work ／ Education |
| 学習ログ ／ コード断片 ／ 問題を解いた記録 ／ 技術メモ | Learning Log ／ Snippet ／ Problem Solving ／ Tech Memo |
| 現在 | Present |
| 英語のみ（/ja で英語だけの中身に出す） | Japanese only（/en で日本語だけの中身に出す） |
| サイトを見る | Visit site |
| 詳細を見る | View details |

## 2. ユーザーロールとフロー

### 2.1 ロール定義

| ロール | 概要 | 主な操作 |
|---|---|---|
| 訪問者 | 採用担当・リクルーター、フリーランスの依頼主、エンジニア仲間など、サイトを見に来る人。ログインしない | 公開側の全画面の閲覧。セクション内ページング、詳細ページの閲覧、外部リンク・GitHubを開く、言語とテーマの切り替え |
| 管理者 | サイトの持ち主（自分）1人。GitHubアカウントでCMSにログインする | 経歴・作品・プロジェクト・ブログ・コーディング記録の作成・編集・下書き保存・公開・非公開化・削除。プロフィールの編集（1件だけで、下書き・削除はない）。使用技術の作成・編集・削除（下書き・公開はなく、トップに出すかを選ぶ）。並べ替え、画像のアップロード |

### 2.2 フロー全体像

```
訪問者（コアフロー「何者かつかみ、作品で確かめる」）:
  トップを開く → プロフィールと経歴で要点をつかむ
  → 同じページの作品欄・プロジェクト欄をセクション内でページングして見る
  → 行を広げる → 広げた中の「詳細を見る」で作品詳細／プロジェクト詳細（背景・工夫・使用技術・画像）
  → 外部リンクやGitHubで実物を確かめる（別タブ）
  ※ 詳細のない作品・プロジェクトは、行を広げた中の外部リンク・GitHubへ進む

訪問者（人となりを知る）:
  トップのブログ欄／コーディング記録欄をページングして見る → ブログ記事／コーディング記録詳細を読む → トップの該当セクションへ戻る

管理者（書いて公開する）:
  管理画面のURLを開く → GitHubでログイン → ダッシュボード
  → 各管理画面の一覧 → 新規作成または編集 → 下書き保存 → プレビューで確認 → 公開
  → 公開サイトで確認
```

| # | 画面名 | 目的 | レイアウト | 認証 | 説明 |
|---|---|---|---|---|---|
| A1 | ログイン | 管理者だけが入る | L3 中央カード | 不要 | 「GitHubでログイン」ボタンだけを置く。管理者として登録したGitHubアカウントだけを通す |
| A2 | ダッシュボード | 管理作業の起点 | L4 サイドメニュー＋一覧 | 必要 | 種類ごとの件数（公開／下書き）、下書きの一覧、新規作成の近道、公開サイトへのリンク |
| A3 | プロフィール編集 | プロフィールを更新する | L6 サイドメニュー＋フォーム | 必要 | 名前・肩書き・写真・自己紹介・SNSリンク。1件だけなので一覧ビューは持たない |

| A5 | 作品管理 | 作品を更新する | 一覧: L4、編集: L5 | 必要 | 一覧（表示順の並べ替え）と編集（詳細本文・画像を含む） |
| A6 | プロジェクト管理 | プロジェクトを更新する | 一覧: L4、編集: L5 | 必要 | 一覧（表示順の並べ替え）と編集（詳細本文・画像を含む） |
| A7 | 使用技術管理 | 技術スタックを更新する | 一覧: L4、編集: L6 | 必要 | 一覧（表示順の並べ替え）と編集（名前・アイコン・リンク・トップに表示するか） |

- 新規作成は、各一覧ビューの「新規作成」から、空の編集ビューを開く。
- 管理画面のサイドメニューの並びは、公開側のセクションの並びに合わせる: ダッシュボード、プロフィール、Career、Projects、Lab、Tech Stack、Blog、Coding Log（名前は 1.4 のセクションの名前）。画面IDの番号順とは違う。
- 公開サイトには、管理画面への入口を置かない。管理画面はURLを直接開いて入る。
- 管理画面は検索エンジンに載せない（クロールさせない）。

## 4. デザインシステム

### 4.1 レイアウトパターン定義

| パターン | 名前 | 使う場面 | 構造 |
|---|---|---|---|
| L1 | シングルカラム・ロングページ | 1ページで全体を伝える画面 | 上部に固定しないヘッダー、その下に読みやすい幅の1列で、セクションを縦に積む。画面幅が広くても1列のまま中央に置く。セクションごとにページングできる |
| L2 | 記事カラム | 1つの中身に集中して読ませる画面 | L1と同じヘッダーと、同じ幅の1列。上から「戻るリンク → タイトルとメタ情報 → 画像 → 本文 → 前後のナビ」の順 |
| L3 | 中央カード | 1つの操作だけをさせる画面 | 画面中央に小さなカードを1枚置く。ヘッダーやメニューはない |
| L4 | サイドメニュー＋一覧 | 管理画面で、たくさんの中身を見渡して選ぶ画面 | 左に固定のサイドメニュー、右に上部の操作バー（新規作成・絞り込みなど）と、テーブルや件数カードなどの一覧 |
| L5 | サイドメニュー＋2ペイン編集 | 管理画面で、長い本文を書いて確かめる画面 | 左にサイドメニュー（アイコンだけ）、上に固定の操作バー（表示の切り替え「書く｜並べる｜日英｜プレビュー」を含む）、その下に言語ごとの欄（タイトル・概要）と、表示に合わせた Markdown エディタとプレビュー、右に設定パネル（共通の項目） |
| L6 | サイドメニュー＋フォーム | 管理画面で、短い項目を入力する画面 | 左にサイドメニュー（アイコンだけ）、上に固定の操作バー、その下に1列のフォーム。日英の項目を持つもの（A3・A4）は、操作バーに表示の切り替え「片方｜日英」を置く。Markdownの欄は、ボタンで入力とプレビューを切り替える |

L4〜L6 のサイドメニューは共通で、上から「メニュー項目（3.3 末尾の並び）」、下部に「ログイン中のGitHubユーザー名（@で始まる表示）」「テーマ切り替え」「ログアウト」を置く。編集ビュー（L5・L6）を開いているあいだは、デスクトップ幅でもサイドメニューをアイコンだけにする。

### 4.2 画面 × レイアウト マッピング

| # | 画面 | パターン | スクロール | 根拠 |
|---|---|---|---|---|
| C1 | 見つからないページ | L2 | なし | 公開側の画面と同じヘッダーを出し、迷ったまま離脱させない |
| C2 | エラー | L2 | なし | C1と同じ。ヘッダーのサイト名からトップへ移れる |
| P1 | トップ | L1 | 縦に長い（ページ全体） | 「1ページで伝わる」原則。セクションの続きはページングで見るので、ページの長さは件数が増えても一定に保たれる |
| P2 | 作品詳細 | L2 | 縦（本文の長さ次第） | 1つの作品の背景と工夫を集中して読ませる |
| P3 | プロジェクト詳細 | L2 | 縦（本文の長さ次第） | P2と同じ |
| P4 | ブログ記事 | L2 | 縦（本文の長さ次第） | 長文を読みやすい幅で読ませる |
| P5 | コーディング記録詳細 | L2 | 縦（本文の長さ次第） | P4と同じ。コードブロックが読みやすいこと |
| A1 | ログイン | L3 | なし | 操作はGitHubでログインの1つだけ |
| A2 | ダッシュボード | L4 | 必要に応じて縦 | 全種類の状況を見渡し、次の作業を選ぶ |

### 4.4 ビジュアルデザイン方針

具体的な値（色・フォント・文字の大きさ・余白・角丸・影・動き・サムネイルの縦横比）は `docs/06_design-tokens.json` が持つ。ここには方針だけを書く。

| 項目 | 方針 |
|---|---|
| トーン&ムード | ミニマム。装飾は最小限にして、あとから変更できるようにしておく。見た目はすべてデザイントークン経由で指定し、コンポーネントに色や余白の値を直接書かない。トーンを変えるときはトークンの差し替えで済むようにする。影は浮いている部品（メニュー・ダイアログ・トースト・ドラッグ中の行）にだけ使う。公開側の項目は1行の行にし、セクションは細い区切り線で区切る。枠線のカードは使わない。管理画面も同じトーンにし、面は地の色で分けず区切り線で分ける。状態の札（下書き・公開）は地の無い文字と丸にする。選んだ使用技術は、枠の無い「つまみ・アイコン・表示名・×」を横に並べて折り返す |
| カラーの方向性 | モノトーン（白・黒・グレー）を基調に、アクセント1色。アクセントは、フォーカスの枠、ページングの現在位置、今の言語にだけ使う。一番の操作のボタンとオンのスイッチは濃い無彩色の塗り（ダークモードは明るい無彩色）にする。選択肢の選んだ印・メニューの今いる項目・一覧やダッシュボードのリンクのホバーもアクセントにせず、濃い文字・太さ・下線で示す。サイドメニューの現在地と戻るリンクもアクセントにせず、グレーの文字と濃い文字で示す。本文中のリンクや使用技術のチップのリンクはアクセントにせず、濃い色と下線にする。アクセントの色相は藍（インディゴ）系。ダークモードでは同じ色相のまま、読みやすさ（コントラスト）を保つように明るさを変える。アクセントとは別に、エラー・成功・注意を示す状態の色を最小限持つ（入力エラーの赤字など） |
| タイポグラフィの方向性 | 和文はゴシック体、英文はサンセリフ体。コードと日付・数値は等幅を使う。見出しと本文の差は、サイズと太さだけでつける。公開側の P1 の自己紹介はグレーの本文にし、太字（固有名詞）とリンクだけを濃い色にする。管理画面の入力欄のラベルは小さなグレーの文字にする。L5 のエディタの上のタイトル・概要は枠の無い欄（タイトルは大きめの文字、概要はグレーの文字。空のときは欄の名前を薄く出す）にする |
| ライト/ダークモード | 両対応。初期状態はOSの設定に合わせる。切り替え（OSに合わせる／ライト／ダーク）は、公開側はヘッダー、管理側はサイドメニューの下部に置き、選んだ設定は覚えておく。ログイン画面（L3）には置かず、覚えている設定かOSの設定に従う |
| 情報密度 | 公開側はゆったり（余白を広めにとって読みやすく）。管理側は高密度（一覧性と操作の速さを優先） |
| 画像 | サムネイルは同じ縦横比で切り抜いて揃える（比率は `docs/06_design-tokens.json`）。P1 では作品・プロジェクトの行を広げたときにだけ出す。画像がない中身は、画像の場所を空けずに詰める。代替テキストは、サムネイルはその中身のタイトル、技術アイコンは表示名、写真は名前、本文中の画像は Markdown に書いた代替テキストを使う |
| 動き | 目に見える動きは、ページングの切り替えの横にスライドする短いアニメーションだけにする（ホバーの色の変化や、ダイアログ・メニューの出入りの短いフェードは除く）。OSで「視差効果を減らす」が有効なら、アニメーションなしで切り替える |

- 表示するのは公開中の中身だけ。下書きは出さない。
作品・プロジェクトの広げた中の入口のリンク（広げた中の最後に、この順で横に並べる。無いものは詰める）:

| リンク | 出す条件 | 行き先 |
|---|---|---|
| 詳細を見る → | 詳細本文がある | 作品詳細（P2）／プロジェクト詳細（P3）。同じタブ |
| サイトを見る ↗ | 外部リンクがある | 外部リンクを別タブ |
| GitHub ↗ | 作品で GitHub がある | GitHub を別タブ |

入口のリンクの見た目は本文中のリンクと同じ（濃い色と下線。4.4）。別タブで開くものは ↗ を付け、読み上げに「別タブで開く」を足す。

- 閉じた行の左側（名前）がはみ出すときは、左側を「…」で切る。右側（期間・日付・アイコン）は切らない。広げた経歴・作品・プロジェクトの行は切らずに折り返す（6.1.3）。ブログ・記録の行の切れたタイトルは、詳細ページで読む。
- 言語ラベルの条件は 1.4 のとおり（中身全体の「言語あり」で決める）。
- ブログ・記録の行は、行全体が詳細へのリンクで、ホバーで地の色を変える。経歴・作品・プロジェクトの行のホバーは 6.1.3。
- モバイル（<768px）: 作品・プロジェクトの行はデスクトップ幅と同じく1行で、左に ▸ とタイトル・言語ラベル、右に使用技術。経歴の行は1行目に ▸ と `所属 ~ タイトル`・言語ラベル、2行目に期間。ブログ・記録の行は1行目にタイトル（記録は種類ラベルも）、2行目に公開日と言語ラベル。経歴の2行目（期間）は、広げた中と同じく ▸ の左端から始める（6.1.3）。広げた中のサムネイルは左のまま（幅は同じ）。
- 抜粋の作り方（ページの説明に使う。System Design Doc ADR-019）: 本文の Markdown から記法・見出しの記号・画像・コードブロックを取り除いたテキストの先頭を使う。長さの目安は日本語で約80字、英語で約160字。目安を超えるときは切って「…」を付け、英語は語の途中で切らない（目安の範囲の最後の空白で切る）。取り除いた結果が空なら、抜粋はない。

### 6.4 ログイン（A1）

```
┌──────────────────────────────┐
│                              │
│      ┌──────────────────┐     │
│      │ eastasian 管理画面 │     │
│      │                  │     │

```

| 状態 | 表示・操作 |
|---|---|
| 通常 | 「GitHubでログイン」ボタンだけ。押すとGitHubの認可画面へ移る |
| 認可中・戻り待ち | ボタンを無効にして「ログインしています…」を出す |
| 成功 | ダッシュボード（A2）へ。ログイン前に開こうとした管理画面があれば、そこへ |
| 管理者でないアカウント | 「このアカウントでは管理画面に入れません」と出し、ログインさせない |
| GitHub側でキャンセル | 「ログインがキャンセルされました」と出す。ボタンはそのまま押せる |
| 通信エラー | 「ログインできませんでした。もう一度お試しください」と出す |
| ログイン済みで開いた | ダッシュボードへリダイレクトする。ログイン前に開こうとした管理画面があれば、そこへ。管理者でないアカウントなどの状態を出すために開いたときは移さず、その状態を出す |

ログアウト: サイドメニューの「ログアウト」を押すと、ログインを終えてログイン画面へ移し、「ログアウトしました」と出す。ログアウトに失敗したら画面を移さず、サイドメニューに「ログアウトできませんでした。もう一度お試しください」と出す。

ログインの有効期限が切れたまま管理画面を操作したら（どの管理画面からでも）、ログイン画面へ移す。ログインし直したら、元の画面へ戻す。編集中の内容がある場合は、移る前に「ログインの有効期限が切れました。入力中の内容はこのブラウザに一時保存してあります」と出す。

編集ビューの一時保存（自動退避）: 保存していない変更があるあいだ、編集中の内容をこのブラウザに一時保存する。タブやブラウザが落ちても、ログインの期限が切れても、次に同じ編集ビュー（新規作成の途中なら空の編集ビュー）を開くと、「一時保存した内容があります（14:32）［復元する］［破棄する］」を出す（時刻の書き方は 6.7.4 の保存の状態と同じ）。サーバーの最終保存の方が一時保存より新しければ、2行目に「保存済みの内容の方が新しくなっています」を添える。一時保存がサーバーの内容と同じなら、提案せずに消す。

| 場面 | 一時保存の扱い |
|---|---|
| 編集ビューを開いた直後（まだ何も入力していない） | 書きも消しもしない |
| 復元の提案を出しているあいだ | 書きも消しもしない（保存しても、ログインの期限が切れても、提案した一時保存は答えるまで残す）。「復元する」を押したら、復元した内容を最初の一時保存として扱う。「破棄する」を押したら提案した一時保存を捨て、提案のあいだに入力していれば、その入力で書き直す |
| 入力した | 1秒待って、最後に読んだ・保存した内容（新規作成は空の内容）と違えば書き、同じなら消す |
| 保存に成功した | 送った内容と今の入力が同じなら消す。保存の通信中にさらに入力していれば、今の入力で書き直す。新規作成の初めての保存では、新規作成の一時保存を消して、以後は作成した項目の一時保存にする |
| 削除した・「保存していない変更があります。移動しますか？」で移動を選んだ | 消す |
| ログインの期限切れでログイン画面へ移す | 最新の入力を待たずに書き、確認を出さずに移す。消さない |
| ブラウザ・タブを閉じた、落ちた | 残る |
| ログアウトに成功した | このブラウザのすべての一時保存を消し、ログイン画面へ移るまで書かない |

│  │ │（中でスクロール）  │（追従する）        │ │ GitHub           │

L5（「日英」）は、言語タブを出さず、言語の見出し（言語ありの印と「要確認」）の下に、日本語と英語の言語ごとの欄とエディタを左右に並べる（モバイル幅は縦に積む）。プレビューは出さない。

L6 は、上に固定の操作バー（戻るリンク（プロフィールは無し）・題・状態の札・保存の状態・表示の切り替え・ボタン）、その下に1列のフォーム。「日英」は言語ごとの欄を左右に並べる（モバイル幅は縦に積む）。

操作バー（L5・L6 共通）:

| 要素 | 内容 |

| 左 | 戻るリンク、題（保存した日本語のタイトル、なければ英語のタイトル。新規作成は「{種類の名前} の新規作成」（種類の名前は 1.4 のセクションの名前。例: Lab の新規作成）、プロフィールは「プロフィール」、使用技術は表示名）、状態の札（下書き・公開。状態を持たないプロフィール・使用技術では出さない）、保存の状態（6.7.4） |
| 中 | 表示の切り替え（L5: 書く｜並べる｜日英｜プレビュー。L6 のプロフィール・経歴: 片方｜日英）。見た目はアイコンだけにし（書く: ペン、並べる: 2列、日英: 文と A、プレビュー: 目、片方: 1枚の紙）、名前はホバー・フォーカスでツールチップに出す |
| 右 | ボタンを押せない理由（6.7.4）、ボタン（下書き保存／非公開に戻す・公開する／更新する・削除、プロフィールは保存、使用技術は保存・削除）。削除はごみ箱のアイコンだけにし、名前はツールチップに出す（削除中は「削除中…」の文字）。削除のほかの操作（下書き保存・公開する・更新する・非公開に戻す・保存）は、公開の状態を変えるかどうかが読めるよう文字のまま。1280px 未満の L5 では「設定」ボタンを足し、設定パネルの欄に誤りがあれば「要確認」の印を付ける |

表示の切り替え（L5）:

#### 6.7.1 共通の操作

| 操作 | 結果 |
|---|---|
| 言語タブ（日本語／English） | 言語ごとの入力欄（タイトル・概要・本文など）を切り替える。共通の項目（スラッグ・リンク・使用技術・画像・日付など）はタブの外（L5 は設定パネル）に置く。その言語で「言語あり」（1.4）になっていないタブに印を付ける。「日英」の表示ではタブを出さず、言語の見出しに同じ印を付ける |
| Cmd/Ctrl+S | 今の状態を変えない保存をする。作品・プロジェクト・ブログ・コーディング記録・経歴は、新規作成と下書きでは「下書き保存」（新規作成は作成して URL を置き換える）、公開中では「更新する」と同じ（保存した瞬間に公開サイトにも出る）。プロフィール・使用技術は「保存」。保存していない変更が無いとき、ボタンを押せないとき、確認ダイアログ（削除・非公開に戻す・スラッグの変更・移動の確認）が開いているときは何も送らない。どの場合もブラウザの「ページを保存」は開かない。設定の引き出しと使用技術の検索欄の中でも保存する。日本語入力の変換中は受け付けない |
| 下書き保存 | 入力を保存し、状態は下書きのまま（公開中のものを編集しているときは、このボタンの代わりに「非公開に戻す」を出す） |
| 公開する | 入力を保存して公開する。ブログ・コーディング記録で公開日が空なら、公開日を今の日時にする |
| 更新する | 公開中のものを編集しているときに出す。保存すると公開サイトにも反映される。ブログ・コーディング記録では、タイトルか本文（どちらかの言語）が変わっていれば、更新日を今の日時にする。非公開のあいだの変更では、更新日を変えない |
| 非公開に戻す | 確認ダイアログ「公開サイトから見えなくなります」を出し、「非公開に戻す」を押すと下書きに戻す。保存していない変更があれば一緒に保存する。編集ビューに残り、状態を下書きにして「非公開に戻しました」と通知する。公開日は消さずに残し、もう一度公開しても変えない（変えたいときは公開日の欄で直す） |
| 削除 | 確認ダイアログ「『△△アプリ』を削除します。元に戻せません」で「削除する」を押すと完全に消し、一覧ビューへ戻って「削除しました」と通知する |
| 画像のアップロード | 画像欄（サムネイル・写真・技術アイコン）では、画像を選ぶかドラッグ＆ドロップする。設定済みの画像はプレビューで見せ、「差し替える」「外す」を置く。サムネイルのプレビューは、公開側と同じ縦横比で切り抜いて見せる（公開側でどこが切れるか分かるように）。Markdownエディタでは、画像を貼り付けるかドロップするか、エディタの下の「画像を挿入」でファイルを選ぶと、アップロードしてカーソルの位置（ドロップでは落とした位置）に画像の記法を入れる |
| 本文の検索 | Markdownエディタの中で Cmd/Ctrl+F を押すと、エディタの上に検索の欄を出す |
| 使用技術を選ぶ（A5・A6） | 「+ 追加」で、登録済みの技術を検索して選ぶ。検索の欄は選んでも閉じず、続けて選べる。候補は技術のアイコンと表示名を並べ（アイコンの無い技術は、名前の位置が揃うよう同じ幅を空ける。選んだ技術の並びでは詰める）、選んだ技術には ✓ を付け、もう一度選ぶと外す。Esc か欄の外を押すと閉じる。候補にないときは、表示名を入れて「新しい技術として追加」を選ぶと、その場で技術を作る（識別名は表示名から自動で作る。作り方はスラッグと同じで（6.7.2）、同じ識別名があれば末尾に `-2`、`-3` … を付け、変換して空になるときは `stack` にする。トップの使用技術セクションには出さない設定で作り、出すかどうかとアイコンなどはあとから A7 で決める） |
| 保存後の画面 | どの保存（下書き保存・公開・更新・非公開に戻す）のあとも、編集ビューに残る。新規作成で初めて保存したら、URLを作成した項目の編集ビューのものに置き換える（URLは System Design Doc の4章） |
| プレビュー | L5では、Markdownを書くとプレビューにすぐ反映する（公開サイトと同じ見た目）。プレビューを出すかどうかは表示の切り替えで決める（6.7 の「表示の切り替え」）。L6では、ボタンで入力とプレビューを切り替える |
| 一覧へ戻る・別の画面へ移る | 保存していない変更があれば「保存していない変更があります。移動しますか？」と確認する |
| 新規作成の表示順 | 作品・プロジェクトは先頭に入る（最新の作品を目立たせやすいため）。使用技術とSNSリンクは末尾に入る。どれも、あとからドラッグで動かせる |

#### 6.7.2 画面ごとの入力項目

| 画面 | 言語ごとの項目（日英） | 共通の項目 |
|---|---|---|
| A3 プロフィール編集 | 名前、肩書き、自己紹介（Markdown） | 写真、SNSリンク（サービスを選んでURLを入れる。`other` を選んだときは表示名も入れる。追加・削除・ドラッグで並べ替え） |
| A4 経歴管理 | タイトル、所属、場所、内容（Markdown） | 種類（職歴／学歴。初期値は職歴）、開始年月、終了年月（空なら「現在」） |
| A5 作品管理 | タイトル、概要、詳細本文（Markdown） | スラッグ、外部リンク、GitHub、使用技術（追加・削除・ドラッグで並べ替え。並びがトップの行に出る順になる）、サムネイル |
| A6 プロジェクト管理 | タイトル、概要、詳細本文（Markdown） | スラッグ、開始年月、終了年月（空なら「現在」）、外部リンク、使用技術（A5と同じ）、サムネイル |
| A7 使用技術管理 | なし（技術名は固有名詞なので日英共通） | 識別名、表示名、アイコン画像、リンク、トップに表示するか |
| A8 ブログ管理 | タイトル、本文（Markdown） | スラッグ、サムネイル、公開日（公開後に変えられる） |
| A9 コーディング記録管理 | タイトル、本文（Markdown） | スラッグ、種類（学習ログ／コード断片／問題を解いた記録／技術メモ。初期値は学習ログ）、参考リンク、サムネイル、公開日（公開後に変えられる） |

- A3 プロフィール編集は1件だけなので、「保存」ボタンだけを置く（下書き・公開・削除はない）。保存するとすぐ公開サイトに反映される。
- A7 使用技術管理は下書き・公開を持たない。ボタンは「保存」と「削除」だけ。トップに出すかどうかは「トップに表示するか」で決める。削除するときは、使っている作品・プロジェクトの数を確認ダイアログに出し、削除するとそれらの紐づけも外れる。
- スラッグのルール（作品・プロジェクト・ブログ・コーディング記録）:
  - 形式は半角の英小文字・数字・ハイフンだけ。
  - 自動で作る: 英語のタイトルから作る。同じ種類の中で重複するときは、末尾に `-2`、`-3` … を付ける。英語のタイトルがない、または変換して空になるときは、スラッグを空にする。英語のタイトルがなければ空のままで、公開するときに入力を求める。
  - 自動で追従する条件: 今のスラッグが「今の英語のタイトルから作った値」と同じで、かつ公開したことがないあいだは、英語のタイトルを変えるとスラッグも変わる。手で別の値に直したら、それ以降は追従しない。
  - 「公開したことがある」の判定: 作品・プロジェクトは初めて公開した日時が、ブログ・コーディング記録は公開日が記録されていること。
  - 公開したことがあるもののスラッグを変えたら、欄の下に「今のURLは見られなくなります」と出し、保存するときにも確認ダイアログを出す。
  - 追従のあいだに英語のタイトルを変えたら、新しいスラッグができるまで保存・公開のボタンを押せない（古いスラッグで保存しないため）。

#### 6.7.3 入力チェック

| 対象 | ルール | 出し方 |
|---|---|---|
| 下書き保存・非公開に戻す | タイトルが日英のどちらかに入っていること（プロフィール・使用技術を除く）。スラッグ・開始年月は空でも保存できる | 入力欄の下に赤字で理由を出し、保存しない |
| 文字数 | 上限のある欄（タイトル・名前・所属・場所・肩書き・表示名・概要。上限は System Design Doc の5.0）は上限の中であること。数え方は前後の空白を除いた文字列の長さ | 上限の8割を超えたら欄の右下に「n / 上限」を出し、上限を超えたら赤字にする。入力は止めず、保存のときに理由を出す |
| 公開する・更新する | 少なくとも1つの言語で「言語あり」になっていること（1.4）。スラッグが入っていること（作品・プロジェクト・ブログ・コーディング記録）。経歴は開始年月が入っていること。プロジェクトは開始年月が入っていること | 足りない項目を一覧で出し、該当する言語タブと入力欄に印を付ける |
| スラッグ | 入っていれば、形式が正しく、同じ種類の中で重複しないこと | 入力欄の下に理由を出す |
| プロフィールの保存 | 名前が日英のどちらかに入っていること | 入力欄の下に理由を出す |
| 使用技術の保存 | 識別名と表示名が入っていること。識別名はスラッグと同じ形式で、重複しないこと | 入力欄の下に理由を出す |
| 日付 | 開始年月と終了年月の両方が入っていれば、終了年月は開始年月と同じか後であること。ブログ・コーディング記録の公開日は、日付と時刻で入れる。今より後にはできず、一度公開したものは空にできない | 入力欄の下に理由を出す |
| SNSリンク | サービスが `other` のときは、表示名が入っていること | 入力欄の下に理由を出す |
| URL | 外部リンク・GitHub・参考リンク・SNSリンク・使用技術のリンクは `https://` で始まること | 入力欄の下に理由を出す |
| 画像 | 画像ファイルであること、大きさの上限内であること（上限と形式は System Design Doc の5.10） | アップロードを止め、「画像ファイルではありません」か「ファイルが大きすぎます（上限 {上限}）」と通知する |

保存しようとして誤り（入力チェック・公開に足りない項目・スラッグの重複）があれば、「確かめる項目があります（{件数}件）」と通知し（件数は、誤りのある欄の数と、欄に結びつかない理由の数の和）、最初の誤りの欄へスクロールしてフォーカスを移す。「最初」の順は、言語ごとの欄（日本語 → 英語。各言語の中は画面の上から）→ 本文（日本語 → 英語）→ 設定パネルの欄（画面の上から）。L6 は画面の上から。移る先が隠れた言語タブの中ならそのタブに切り替え、設定の引き出しの中なら引き出しを開き、「プレビュー」の表示で本文に誤りがあれば「書く」に切り替える。「日英」の表示では両方の言語が見えているので、タブは切り替えない。

#### 6.7.4 状態ごとの表示

| 状態 | 表示 |
|---|---|
| 新規作成 | 入力欄が空の編集ビュー。状態は「下書き（未保存）」、保存の状態は「未保存」 |
| 読み込み中 | 入力欄にスケルトン（L5 は L5 の形のスケルトン）。保存・公開ボタンは無効 |
| 保存の状態（操作バー） | 変更なし: 「保存済み 14:32」（時刻は最後に読んだ・保存したサーバーの最終保存。日本時間。今日でなければ「保存済み 10月6日 14:32」）。保存していない変更あり: 「● 未保存の変更」。保存中: 「保存しています…」 |
| ボタンを押せない | 保存・公開のボタンと Cmd/Ctrl+S を止め、ボタンの左に理由を出す: 「保存しています」「画像をアップロードしています」「スラッグを作っています」 |
| 保存中 | ボタンを無効にし、押したボタンに読み込み中の印を出す |
| 保存に成功 | 「保存しました」「公開しました」などを短く通知する |
| 保存に失敗 | 「保存できませんでした。もう一度お試しください」と出し、入力した内容は消さない |
| 画像のアップロード中・失敗 | エディタに「アップロード中…」を出す。本文のエディタと画像欄（サムネイル・写真・技術アイコン）のどれかがアップロード中のあいだは、保存・公開のボタンと Cmd/Ctrl+S を止める（仮の記法や古い画像を保存しないため）。プレビューには仮の記法を出さない。失敗したら仮の記法を消し、理由を通知する。画像欄では欄に読み込み中の印を出し、失敗したら元の画像を残したまま理由を通知する |
| 取得に失敗 | 「読み込めませんでした」と「再試行」を出し、保存・公開ボタンは無効にする |
| 削除に失敗 | 「削除できませんでした」と出し、編集ビューに残る |
| 存在しないIDを開いた | 編集ビューの中に「見つかりませんでした」と「一覧へ戻る」を出す（C1 は使わない） |
| プロフィールがまだない（A3） | 空のフォームを出す。初めて保存したときに作る |

### データ移行

- 今の公開サイト（https://eastasian.vercel.app/）のトップページに埋め込まれたデータ（`__NEXT_DATA__`）から、プロフィール・経歴・作品・プロジェクト・使用技術を抽出し、System Design Doc の6章の形に変換して移す。日英は1つのページに両方入っている（英語のフィールドと `…Jp` のフィールド）。
- 今の作品・プロジェクトの説明（Work.body・Project.body）は、新しい `summary`（概要）に入れる。詳細本文は移行後に書き足す。日英のどちらかの説明が概要の上限（System Design Doc 5.0 の500字）を超える中身は、日英とも詳細本文に入れて概要を空にする（概要は公開の前に書き足す）。
- 今の経歴は所属・場所を1つの値で持ち、日英どちらのページにも同じ値を出していた。所属・場所は日英の両方に同じ値を入れる。プロフィールの肩書きは今のサイトに無いので空で入れる。
- 期間（経歴・プロジェクトの開始・終了）は、今の日時を日本時間の年月にして入れる。
- 自己紹介・経歴の内容・詳細本文は、今のテキストをそのまま Markdown として入れる。段落の中の1つの改行は Markdown では改行にならず前後の行がつながって表示されるので、管理画面で確認するときに直す。
- 使用技術は、トップの「仕事」「個人開発」の欄と、作品・プロジェクトにだけ紐づく技術を重複なく集める。表示順は「仕事」の欄の順で、その後ろに残りを並べる。トップには、今のトップの欄に出ていた技術だけを出す。識別名は、今の識別名（`name`）から 6.7.1 と同じ作り方（同じ識別名があれば末尾に `-2`、`-3` … を付け、変換して空になるときは `stack`）で作る。
- 作品・プロジェクトのスラッグは、英語のタイトルから 6.7.2 と同じ作り方で作って入れておく。
- 画像（写真・技術アイコン）は、今の置き場（`plmzmwpmjruswencnerh.supabase.co`）から新しい保存先へ移す。アップロード（System Design Doc 5.10）と同じ形式・大きさ・先頭のバイトの検査を通す。
- 公開状態を持つ経歴・作品・プロジェクトは下書きで入れ、管理画面で確認してから公開する。公開状態を持たないプロフィール・SNSリンク・使用技術は、入れた時点で公開サイトに出る。
