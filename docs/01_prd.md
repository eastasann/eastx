# PRD — eastx

## 1. 概要

eastx は、個人のレジュメ／ポートフォリオサイト eastasian（https://eastasian.vercel.app/）を作り直したもの。日英2言語の公開サイト（https://x.eastasian.dev）と、自作の CMS（管理画面）からなる。サイト名は今のものを引き継ぎ（design-spec 6.1.2）、ドメインだけを変える（eastx はこのプロジェクトとリポジトリの名前）。公開サイトのヘッダーにはサイト名ではなくドメイン名を出す（design-spec 6.1.2）。

公開サイトはトップの1ページで「何ができる人で、どんな経歴か」を伝え、作品・プロジェクトの詳細で実力を確かめてもらい、ブログとコーディング記録で考え方や学びの過程を見せる。持ち主は自作の CMS から、手間をかけずに中身を更新する。サイトの作り方そのものも、技術力を示す作品として見せる。

画面と振る舞いの正は `docs/design-spec.md`、技術の構成は `docs/02-01_system-design-doc.md`。

## 2. 背景と目的

### 背景

今のサイトには次の4つの課題がある（`docs/concept.md`）。

| 課題 | 中身 |
|---|---|
| 技術が古く、保守がつらい | Nx モノレポ、Next.js Pages Router、Redux/Zustand/Mantine 5、別ホストの Express API など、構成が重くて手を入れにくい |
| CMS での更新が面倒 | 自作の管理画面での更新に手間がかかる |
| 見せ方・デザインが今の自分に合っていない | 1ページのレジュメ形式とデザインを刷新したい |
| 載せたい中身を載せる場所がない | レジュメ以外（ブログ、コーディング記録）を置けない |

### 目的

1. **ポートフォリオ**: 転職や案件獲得のために、自分を見せる場所を整える。
2. **サイト自体を作品にする**: 作り方や設計（技術選定・API 設計・デザイントークン）を、技術力を示す実績にする。
3. **自分の記録の場所**: 経歴や学びを、自分のために積み上げていく。

マネタイズはしない。レジュメ・作品・プロジェクト・ブログ・コーディング記録・自作 CMS をすべてそろえてから、一度に公開する。

## 3. ターゲットユーザーと課題

ロールは design-spec 2.1 の「訪問者」と「管理者」。訪問者はペルソナごとに分ける。

| ロール | ペルソナ | 課題 |
|--------|---------|------|
| 訪問者 | 採用担当・リクルーター。候補者を短時間で見極めたい | 経歴とスキルを数分でつかみたいが、詳しく知る手がかり（作品の背景、考え方）が少ない |
| 訪問者 | フリーランスの依頼主。仕事を頼む前に実績を確かめたい | 作品の見た目やリンクだけでなく、背景・工夫・使った技術まで確かめたい |
| 訪問者 | エンジニア仲間・コミュニティ。ブログやコーディング記録を読みに来る | 技術的な考え方や学びの過程を読める場所がない |
| 管理者 | サイトの持ち主（自分）1人 | 更新に手間がかかり、ブログ・記録の置き場所がない。構成が重く、サイトに手を入れにくい |

訪問者は日本語と英語のどちらでも読み、スマホと PC の両方から来る。

## 4. 主要機能（ユーザーストーリー）

優先度: **Must**（公開に必須）／ **Should**（公開時にそろえたい。遅れたら公開後すぐに足す）／ **Could**（余裕があれば）。各ストーリーの画面と振る舞いは、括弧の中の design-spec の章を参照する。

### 訪問者として

| # | ストーリー | 優先度 |
|---|-----------|--------|
| V-1 | トップを開いたら、プロフィールと経歴を見るだけで、何ができる人かをつかみたい（6.1） | Must |
| V-2 | 作品・プロジェクトを、ページを移らずに次々と見比べたい（6.1.3） | Must |
| V-3 | 詳細のある作品・プロジェクトで、背景・工夫・使用技術・画像を読みたい（6.2） | Must |
| V-4 | 気になった作品の実物（公開中のサイト・GitHub）を、別タブで確かめたい（6.1.4・6.2.2） | Must |
| V-5 | 使用技術の一覧で、扱える技術を一目で把握したい（6.1.4） | Must |
| V-6 | ブログ記事を読んで、考え方を知りたい（6.3） | Must |
| V-7 | コーディング記録を読んで、学びの過程や興味を知りたい（6.3） | Must |
| V-8 | 日本語と英語を切り替えて、同じ画面を自分の言語で読みたい。片方の言語しかない中身は、そうとわかるようにしてほしい（1.4） | Must |
| V-9 | スマホでも PC でも、同じように読みたい（4.3） | Must |
| V-10 | 詳細ページから戻ったとき、見ていたセクションのページに戻りたい（6.1.3） | Should |
| V-11 | ライトとダークを切り替えたい。最初は OS の設定に合わせてほしい（4.4） | Should |
| V-12 | SNS で共有されたリンクで、タイトルと画像からどんなページかわかるようにしてほしい | Should |
| V-13 | キーボードやスクリーンリーダーでも、ページングを操作したい（6.1.3） | Should |

### 管理者として

| # | ストーリー | 優先度 |
|---|-----------|--------|
| M-1 | 自分の GitHub アカウントで管理画面にログインしたい。ほかの人は入れないようにしたい（6.4） | Must |
| M-2 | ダッシュボードで種類ごとの件数と下書きを見渡して、次の作業を選びたい（6.5） | Must |
| M-3 | プロフィール（名前・肩書き・一言・写真・自己紹介・SNS リンク）を日英で更新したい（6.7.2） | Must |
| M-4 | 経歴を日英で追加・編集し、下書きから公開したい（6.6・6.7） | Must |
| M-5 | 作品とプロジェクトを、詳細本文・画像・使用技術つきで書き、表示順をドラッグで変えたい（6.6・6.7） | Must |
| M-6 | 使用技術を登録して、トップに出すものと順番を決めたい。作品の編集中に、新しい技術をその場で足したい（6.7.1） | Must |
| M-7 | ブログ記事とコーディング記録を Markdown で書き、プレビューで確かめてから公開したい（6.7） | Must |
| M-8 | 画像を貼り付けやドロップでアップロードして、本文や画像欄に入れたい（6.7.1） | Must |
| M-9 | ブログ記事とコーディング記録は、公開後に本文やタイトルを直したら更新日が付くようにしたい。どの中身も、必要なら非公開に戻したい（6.7.1） | Must |
| M-10 | 保存した変更が、デプロイなしですぐ公開サイトに出てほしい | Must |
| M-11 | 今のサイトのデータを移して、最初から中身のある状態で公開したい（9章） | Must |
| M-12 | ログインの期限が切れても、書きかけの内容を失いたくない（6.4） | Should |

### 持ち主（開発者）として

| # | ストーリー | 優先度 |
|---|-----------|--------|
| D-1 | 本番に出す前に、staging で同じものを確かめたい。出すのもロールバックも PR で行いたい | Must |
| D-2 | エラーやサイトの停止に、メールで気づきたい | Must |
| D-3 | 構成を小さく保ち、依存の更新や機能の追加を気軽にしたい | Must |
| D-4 | サイトの設計（ADR・API・デザイントークン）を、ポートフォリオとして見せられる形で残したい | Should |

## 5. 成功指標（KPI）

アクセス解析はしない（スコープ外）ので、測れるものに絞る。

| 指標 | 目標 |
|------|------|
| Lighthouse（モバイル。P1 と、P2〜P5 から各1ページ） | Performance 90 以上、Accessibility 95 以上、Best Practices 95 以上、SEO 95 以上 |
| P1 の表示の速さ | TTFB が日本から p75 で 500ms 以下（測り方は System Design Doc 7章） |
| 更新の手間 | 下書きから公開まで管理画面だけで完結し、デプロイが要らない。既存の項目を直して公開し直すまで1分以内 |
| データ移行 | 今のサイトのプロフィール・経歴・作品・プロジェクト・使用技術を、日英とも欠けなく移す |
| 発信の継続 | 公開から3か月で、ブログ記事5本・コーディング記録10本を公開する |
| 安定性 | 月間の稼働率 99.9% 以上（Sentry の稼働監視）。Sentry の未対応のエラーを、定期の棚卸し（頻度は `docs/05_operation-runbook.md` 6章）で0件に保つ |
| 運用のコスト | 固定費を Workers Paid（月 $5）とドメイン代に収める |

## 6. スコープ外

機能の拡張候補は design-spec 9章「拡張候補」が持つ。加えて、次のものも作らない。

- 複数の管理者、権限の細分化、共同編集
- 訪問者のアカウント、コメント、いいね、通知
- 日本語と英語以外の言語
- 有料の機能、広告
- ネイティブアプリ、外部向けの公開 API
- 外部の CMS（Contentful など）や BaaS の管理画面での更新
